# 文件結構與生命週期

文件按讀者問題與資訊責任組織。先從[產品入口](../../README.md)理解用途，再由[索引](DOCUMENTATION_INDEX.md)選正文。

## 內容責任

| 類型 | 內容與維護 |
|---|---|
| 權威正文 | 現況、產品標準、契約或操作，各有明確範圍；更新對應章節並連支持來源 |
| 導覽 | README、Index、路由與地圖；說明去哪裡及何時讀，不複製狀態 |
| 主題分冊 | 現行詳細契約／操作；由主文帶入，依問題閱讀 |
| 證據 | 固定版本、日期、環境與範圍的驗收；保留原結果與限制 |
| 歷史 | 被取代設計、結束計畫、舊快照與原bytes；有替代入口及恢復 |

權威分工見[文件覆蓋地圖](DOC_COVERAGE_MAP.md)。架構、操作手冊與現況快照整合現行內容；每輪測試與處理過程保存於 QA 或歷史。

## 新增、拆分與刪除

1. 先核既有主題是否可容納；同一問題優先整合，不為每輪進度新增active文件。
2. 新文件有scope、領域owner、上層導航及相關功能／測試；有產品或工程影響時完成Coverage。
3. 拆分先保存原bytes與SHA；仍成立的契約移入正文，不能只封存全文而遺失現行內容。
4. QA／計畫的日期、完成標籤或缺連結不是刪移理由；先核未解Gate、入站引用、依賴、固定產物與替代證據。
5. 可移除內容限已核冗餘、無唯一資訊的本任務副本或被取代純模板；記理由與恢復。不清理正式資料或他人變更。
6. 更新領域索引與入站連結；必要的相容anchor集中在後方查找區，不把舊日誌放回章首。

仍在QA原位置的證據必須由主題索引可達；未分類列待判定，不直接刪。與31項refactor任務及驗收／回滾綁定的報告保留集合，不批次移出。

### QA 證據保留與封存

<a id="qa-evidence-retention"></a>

`docs/06_qa/` 保存具時間與範圍的驗收證據；日期、完成標籤或文件長度本身不決定歸檔。若證據仍被 Gate、開放問題／重驗、Roadmap、Manual、測試、腳本或固定輸出路徑引用，或是現行 scoped contract、唯一入口、尚未被取代的最新驗收，就留在 QA。只有 owner／Gate 已結案、未解事項與替代入口已交代，而且活躍路徑依賴已解除或保留相容入口，才將純歷史收據移到 Archive。

保留舊路徑短導引；Coverage History 記錄原路徑、封存位置、原件 bytes／hash、當時效力與目前替代入口。若產生器仍寫入固定 QA 路徑，先處理 writer／consumer 契約；redirect 不能取代原始證據。

## 本機狀態與精確原件

`output/tasks/<task_id>/task.json` 由單一負責者維護，是被 Git 忽略的本機協作狀態。它不取代產品現況快照；舊的共用交接檔仍由原負責者維護。原始 QA 輸出、私人清冊與 Graphify 產物依[Git 排除規則](../agents/git_exclusions.md)保存並另作必要備份。

本輪[exact-byte originals](../09_archive/documentation_productization_20261012/README.md)保持原bytes，引用按原路徑語境解讀；現行導航核查不把它當active正文。這項明示例外不適用於其他現行／新增文件。恢復前核SHA、owner及現在diff，只撤回授權的精確範圍。

## 閱讀與交付驗收

入口解釋用途、現況回答限制、架構能用圖與責任理解、Manual能走使用流程、移機Prompt能產出完整清冊與驗收計畫。Root核正文、關聯、連結、原件與scope；結構工具通過不等於語意或產品Gate通過。
