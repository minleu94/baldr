## 範圍與前置條件

此矩陣補上 C1 原 bundle 未覆蓋的 consumer-required-field、異質歷史讀取及交錯身分案例。它沿用 `REFACTOR_VALIDATION_MATRIX.md` 的 V-REC、V-EXEC、V-CODEC、V-PERSIST、focused V-ML-SMALL gate，以及 R005 的 replay oracle；不改策略、分數、排序、producer policy 或既有歷史 bytes。

- 所有新例只用 `tmp_path` 與合成資料；不得讀寫正式 `DATA_ROOT`、重建全市場資料、執行 scheduler、啟動或修改 `scripts/scheduled/run_scheduled_recommendation_snapshot.py` 的 main、訓練／promotion 或寫入 formal child artifact。C1 使用合成 artifact／producer hash oracle；真 scheduled wrapper parity 是 C1 後 R014 的接線 gate。
- 時間值固定且帶 timezone。缺少可得時間的舊欄位保持 unknown；不得以測試當下時間、今日資料、`last_*`、目前 model 或 active pointer 補值。
- 合成 bytes fixture 可在測試 manifest 固定期望 SHA-256，以確保測試輸入穩定。對未保存可信歷史 digest 的舊 legacy 檔，read-time SHA-256 只識別當次讀到的位元組，不能偵測此前竄改；測試只比較該次讀取前後 bytes 是否保持，不宣稱歷史 authenticity。只有另有獨立可信 hash manifest 時，才測試 hash mismatch 拒絕。
- readiness 測試與 synthetic fixtures 已實作，並已由 final QA 執行；結果見 `C1_FULL_GATE_VALIDATION_REPORT.md`。下方案例表保留原建議名稱作需求追溯，未執行案例不得因此視為通過。
- R014 若需擴充 execution 欄位、R016 若需擴充 unified query／legacy dispatch，先交 SOL 裁決。R017 依 SOL 選項 2 暫行：TMP-REC-04 只透傳外層 legacy snapshot，typed child 只映射已知 production row 欄位；實際 production annotation 與 TMP 退場留給 R020。不得以 `extended_attributes`、第二 writer、任意 mapping 或偽造 reference 繞過。
