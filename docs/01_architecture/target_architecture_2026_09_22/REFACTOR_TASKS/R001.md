# R001 — 凍結實作基線、caller 與 artifact 清冊

## TASK CONTEXT

本任務是整個重構 DAG 的零號入口。現況有未提交架構文件與未追蹤 `=`；推薦、保存、replay、策略與 ML caller 分散在 app、Qt、scripts、tests，不能只靠 import graph 判斷。

## WHY THIS TASK EXISTS

後續任務要能證明「全部 consumer 已遷移」及「歷史／模型 ABI 可保留」。沒有精確清冊就不能安全刪 façade、DTO path 或 serialized alias。

## AUTHORITATIVE ARCHITECTURE REFERENCES

- [FINAL_MIGRATION_SEQUENCE §2、§7](../FINAL_MIGRATION_SEQUENCE.md)
- [FINAL_ARCHITECTURE_INVARIANTS INV-01、17、18](../FINAL_ARCHITECTURE_INVARIANTS.md)
- [FINAL_ML_COMPATIBILITY_CONTRACT §5、§6、§8](../FINAL_ML_COMPATIBILITY_CONTRACT.md)

## DEPENDENCIES

無。開始前記錄 HEAD、branch/worktree、dirty files、Python/依賴版本與資料root設定。

## ALLOWED SCOPE

- 新增一份 `docs/06_qa/` 基線清冊及必要的唯讀 inventory script/test。
- 搜尋 `app_module/`、`ui_qt/`、`scripts/`、`runtime/`、`development_module/`、`tests/`。
- 唯讀列出 ML manifests、schema/version、qualified class paths；不反序列化未知artifact。

## OUT OF SCOPE

Production code、資料／模型／checkpoint、現有測試語意、任何 migration 實作。

## CURRENT BEHAVIOR TO PRESERVE

清冊必須記錄 `run_recommendation`、所有 `last_*`、RecommendationDTO/ResultDTO、repository save/load、replay dict、StrategySpec/Registry、regime state、ML calibration/direct identity 的 direct、dynamic、string與serialized使用。

## IMPLEMENTATION OBJECTIVE

每筆 caller 至少有 path、symbol、call mode、read/write權限、目前contract、預定遷移task、外部支援狀態。另建立artifact ABI清冊與九個既定 TMP 狀態。

## ARCHITECTURAL INVARIANTS

INV-01、02、15、17、18。清冊不是架構例外；未知資料標 unknown。

## ML COMPATIBILITY REQUIREMENTS

列出15條Direct dependencies、feature/label schemas、model/class-path/checkpoint consumers。不得載入未知joblib或改hash。

## PERSISTENCE COMPATIBILITY REQUIREMENTS

記錄 JSON schema/keys、SQLite index、replace/create-only writers、orphan recovery、所有讀者與artifact留存範圍。

## TEST REQUIREMENTS

inventory command可重跑、有輸出上限、排除cache/output；`git diff --check`；證明無production變更。

## ACCEPTANCE CRITERIA

所有 DAG 已知入口均有owner；沒有「待搜尋」空欄；dynamic/serialized與repo caller分開；其他agent dirty files未被改動。

## EXPECTED DELIVERABLES

基線清冊、搜尋命令與輸出摘要、artifact ABI表、TMP表、known gaps。

## POST-TASK REPORT REQUIREMENTS

報告 exact HEAD、dirty preservation、caller/artifact筆數、unknown項、後續task mapping、未執行事項。

## ROLLBACK / FAILURE CONDITIONS

若清冊無法判定owner或需寫正式資料才能盤點，停止並回報 blocker。回滾只刪本task新增文件/script，不動原檔。
