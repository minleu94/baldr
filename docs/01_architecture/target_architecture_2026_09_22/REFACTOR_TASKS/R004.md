# R004 — 保存、舊格式與故障復原 characterization

## TASK CONTEXT

現有RecommendationRepository同時有replace與create-only；JSON artifact及SQLite index沒有跨介質原子性。Personalization測試已有並行／orphan案例，但需形成新保存路徑的獨立oracle。

## WHY THIS TASK EXISTS

R009/R012會發布新wire與save API。格式或中斷語意若未先固定，回滾後可能無法讀舊結果。

## AUTHORITATIVE ARCHITECTURE REFERENCES

- [FINAL_TARGET_ARCHITECTURE §6](../FINAL_TARGET_ARCHITECTURE.md)
- [FINAL_DATA_FLOW §3](../FINAL_DATA_FLOW.md)
- [FINAL_ARCHITECTURE_INVARIANTS INV-11、12](../FINAL_ARCHITECTURE_INVARIANTS.md)

## DEPENDENCIES

R001。

## ALLOWED SCOPE

新增tmp-path persistence characterization；建立舊JSON/SQLite fixture copy與failure injection。

## OUT OF SCOPE

新codec/store、改DB schema、刪replace、寫正式output。

## CURRENT BEHAVIOR TO PRESERVE

DTO English/Chinese keys、Decimal price、screening/why-not/liquidity、create-only identical bytes recovery、unknown existing bytes拒絕、concurrent first-writer、watchlist/ACK soft failure。

## IMPLEMENTATION OBJECTIVE

明確記錄replace與create-only不同語意；測artifact-only/index-only、same ID/hash、same ID/different bytes、label/name變更、load/list結果。

## ARCHITECTURAL INVARIANTS

INV-01、11、12、17。

## ML COMPATIBILITY REQUIREMENTS

保存的projection/receipt IDs與hash當不透明受驗欄位；不重新推論。

## PERSISTENCE COMPATIBILITY REQUIREMENTS

全部fixture在tmp_path；原bytes先hash再decode；任何unknown格式保留原檔。

## TEST REQUIREMENTS

新增專用測試；跑DTO roundtrip、save coordinator、personalization save integration。注入file/index失敗與並行寫入。

## ACCEPTANCE CRITERIA

原路徑的成功與拒絕均可重跑；save-time regime重查被標為gap而非golden；沒有正式寫入。

## EXPECTED DELIVERABLES

fixture、failure-window matrix、舊writer/reader清冊補充。

## POST-TASK REPORT REQUIREMENTS

報告每個failure point、保留bytes/hash、恢復方式、目前replace caller。

## ROLLBACK / FAILURE CONDITIONS

若無法隔離writer或fixture會讀正式root，立即停止。回滾移除新增測試資料。
