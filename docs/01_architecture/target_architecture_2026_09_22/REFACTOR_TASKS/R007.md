# R007 — 建立 data leaf observation／availability contracts

## TASK CONTEXT

目前data與decision以多種dict/record交換來源欄位，部分data modules直接import factor DTO。FINAL要求data leaf contract無I/O、無app/domain import。

## WHY THIS TASK EXISTS

R018、R021、R023、R024與R010需要共同、窄且可凍結的來源事實，不應各自再建mapping。

## AUTHORITATIVE ARCHITECTURE REFERENCES

- [FINAL_TARGET_ARCHITECTURE §3–§5](../FINAL_TARGET_ARCHITECTURE.md)
- [FINAL_ARCHITECTURE_INVARIANTS INV-02–05](../FINAL_ARCHITECTURE_INVARIANTS.md)

## DEPENDENCIES

R001。

## ALLOWED SCOPE

新增 `data_module/contracts/market.py` 與必要窄`__init__`、contract tests；命名須對齊FINAL的SourceObservation/MarketSlice/availability/source refs。

## OUT OF SCOPE

遷移providers/consumers、建立全系統超級DTO、vendor I/O、factor/ML schema、production data。

## CURRENT BEHAVIOR TO PRESERVE

既有date、unit、available_date、revision/source ID、missing/unknown/zero差異；不替舊來源補造clock。

## IMPLEMENTATION OBJECTIVE

用frozen、typed leaf records表達標準事實與來源custody；禁止DataFrame/live connection/latest pointer作sealed值。

## ARCHITECTURAL INVARIANTS

INV-02、03、04、05、08。

## ML COMPATIBILITY REQUIREMENTS

這些是來源事實，不是feature registry；不得改或複製ML ordered schema。ML可依賴leaf types。

## PERSISTENCE COMPATIBILITY REQUIREMENTS

本task不發布wire；若提供to/from primitive僅供tests，不能建立另一codec。

## TEST REQUIREMENTS

immutability、timezone/date、unit/revision、unknown/None/zero、duplicate identity；import smoke證明無I/O與逆向imports。

## ACCEPTANCE CRITERIA

contract可被data/analysis/decision/ML leaf import；import不開DB/檔案；沒有`Any`逃生bag或超級payload。

## EXPECTED DELIVERABLES

contract module、tests、欄位owner說明。

## POST-TASK REPORT REQUIREMENTS

列出公開types、validation、未遷移consumer及無I/O證據。

## ROLLBACK / FAILURE CONDITIONS

若需求迫使contract import app/domain或包含provider方法，停止並回報架構矛盾。未接consumer前可整體回滾。
