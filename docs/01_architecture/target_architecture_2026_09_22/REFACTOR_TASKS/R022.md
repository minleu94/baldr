# R022 — regime policy／state transition 與 I/O 分離

## TASK CONTEXT

MarketRegimeDetector目前持有history、load/save與計算；RecommendationSaveRequest保存時可能重detect。FINAL要求prior state/transition明示，保存execution-time regime。

## WHY THIS TASK EXISTS

直接移除history I/O會讓hysteresis失效；這項需以多日sequence獨立驗收。

## AUTHORITATIVE ARCHITECTURE REFERENCES

- [FINAL_TARGET_ARCHITECTURE §5.2](../FINAL_TARGET_ARCHITECTURE.md)
- [FINAL_MIGRATION_SEQUENCE Block 4](../FINAL_MIGRATION_SEQUENCE.md)
- [FINAL_ARCHITECTURE_INVARIANTS INV-03、10、13](../FINAL_ARCHITECTURE_INVARIANTS.md)

## DEPENDENCIES

R003、R012、R015。R012 先提供保存 execution-time regime 路徑，R015 完成保存 caller closure 後，本任務才可清除 save-time re-detect。

## ALLOWED SCOPE

market regime pure contracts/kernels/detector、RegimeService state adapter/composition、save-time caller cleanup與tests。

## OUT OF SCOPE

改regime公式/threshold/labels、刪history、改walkforward統計、正式state migration。

## CURRENT BEHAVIOR TO PRESERVE

min confirmation days、cooldown、same-day rerun、target date後history忽略、persistent vs isolated mode、source failure/degraded details。

## IMPLEMENTATION OBJECTIVE

pure detector接受market input＋prior state，回regime＋transition；app負責load/compare-and-write。Execution保存當次值，save不重新偵測。

## ARCHITECTURAL INVARIANTS

INV-03、05、07、10、13、16。

## ML COMPATIBILITY REQUIREMENTS

不改regime refs/labels；任何ML consumer仍看到原值/version。

## PERSISTENCE COMPATIBILITY REQUIREMENTS

保留regime_history格式/path與更新時點；若新versioning需adapter，不破壞舊file；state衝突明示。

## TEST REQUIREMENTS

regime kernels/detector/provider、walkforward hysteresis/isolated、same-day、多日、concurrency、run A→source change→save A。

## ACCEPTANCE CRITERIA

decision無file I/O；歷史行為parity；save不呼叫detect；state失敗不偽裝成功。

## EXPECTED DELIVERABLES

state/transition contracts、app adapter、detector cleanup、tests。

## POST-TASK REPORT REQUIREMENTS

列state schema、transition sequence、save behavior change（FINAL已核准）、parity與rollback。

## ROLLBACK / FAILURE CONDITIONS

hysteresis/cooldown/date任何差異即rollback；不得清空history或補現在值。
