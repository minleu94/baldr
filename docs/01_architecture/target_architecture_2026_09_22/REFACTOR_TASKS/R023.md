# R023 — fundamental／monthly-revenue data contracts 與 factor owner

## TASK CONTEXT

多個fundamental/monthly revenue data modules直接產decision FactorDiagnostic/Quality；decision fundamental adapters也直接吃data records。FINAL要求vendor/availability在data、factor語意在decision。

## WHY THIS TASK EXISTS

R019需要domain-owned factor inputs；先用一個實際vertical建立無逆向依賴的模式。

## AUTHORITATIVE ARCHITECTURE REFERENCES

- [FINAL_TARGET_ARCHITECTURE RT-1裁決、§3–§5](../FINAL_TARGET_ARCHITECTURE.md)
- [FINAL_ARCHITECTURE_INVARIANTS INV-02–05](../FINAL_ARCHITECTURE_INVARIANTS.md)

## DEPENDENCIES

R001、R007。

## ALLOWED SCOPE

fundamental_data/availability/sources/entrypoint/sqlite provider、monthly_revenue availability/history/backfill/harvest相關純contracts；decision fundamental adapters；tests。

## OUT OF SCOPE

statement/valuation、source priority change、資料重抓/回填、factor公式/threshold變更、ML feature新增。

## CURRENT BEHAVIOR TO PRESERVE

available_date/revision、MonthlyRevenueRecord values、quality/missing diagnostics、future row skip、Decimal/int/string unit、source custody與DB read semantics。

## IMPLEMENTATION OBJECTIVE

data回source/availability diagnostics純records；decision將其解讀為FactorRecord/Diagnostic。移除本vertical的data→decision imports。

## ARCHITECTURAL INVARIANTS

INV-02–06。

## ML COMPATIBILITY REQUIREMENTS

existing historical feature builder排除fundamental/broker的契約不變；不修改ML registry/data。

## PERSISTENCE COMPATIBILITY REQUIREMENTS

舊DB/files不migration；adapter讀舊record後產相同factor output。

## TEST REQUIREMENTS

fundamental data/availability/source/provider、fundamental factor adapters、revenue factor pack、future available date與source revision tests；dependency guard。

## ACCEPTANCE CRITERIA

同fixtures得到同FactorRecord/Diagnostic；本vertical data不importdecision；無正式資料改動。

## EXPECTED DELIVERABLES

data records、domain mapping、adapter wiring、tests與mapping表。

## POST-TASK REPORT REQUIREMENTS

列舊/新types、unit/date/missing parity、remaining data→factor imports給R024。

## ROLLBACK / FAILURE CONDITIONS

值/quality/available date差異即逐consumer回切；不能修改data補domain語意。
