# R026 — explicit PreparedMLInput 推論流程

## TASK CONTEXT

推薦 calibration 目前在 `RecommendationService` 內直接解析 provider、建立 historical features、載入模型、執行 projection 並發布 receipt；R010 先建立永久 `ml_adapter.py` 契約與 frozen legacy preparation 分支。

## WHY THIS TASK EXISTS

app 必須明示準備 decision-time 資料與模型，讓 build／infer 只消費 frozen `PreparedMLInput`，同時保留既有讀取時序、模型身分與降級行為。

## DEPENDENCIES

R006、R010、R011、R018。

## ALLOWED SCOPE

`app_module/recommendation/ml_adapter.py`、recommendation execute／composition、原 calibration branch、provider／feature consumer boundaries、receipt wiring 與對應 tests。凍結 ML 檔只可在契約不可避免且有 ABI 證據時最小修改。

## OUT OF SCOPE

重訓、改 feature names／order／dtype／missing policy、改模型輸出、改 rule top-N、移動 Direct 15 paths、變更 artifact hash、loader 拒絕政策或 promotion 狀態。

## CURRENT BEHAVIOR TO PRESERVE

來源與 active pointer 的 resolve 時點、決策日期 cutoff、candidate identity／順序、cost context、feature bytes／order、quarantine／unavailable 降級、projection、annotation、receipt identity，以及 receipt 發布失敗的既有可見結果與副作用次序。

## IMPLEMENTATION OBJECTIVE

app preparation 一次產出深凍結且版本化的 `PreparedMLInput.v1` 身分／reference 契約，並組成版本化 `PreparedMLRuntimeInputV1`。後者是 inference projector 的唯一 runtime 參數，封裝前者、同次 invocation 的 ordered feature input 與 private model/lineage capability；`PreparedMLInput.v1` 本身保持純身分／reference，不承載 mutable model。infer 不再自行查資料、模型或 active pointer。相容驗證通過後，`REMOVES_TEMPORARY_COMPONENT: TMP-ML-01`；永久 `ml_adapter.py` 與舊 artifact decoder／必要 class aliases 保留。

## ARCHITECTURAL INVARIANTS

INV-08–12、INV-16。Rule 與 ML snapshot identity 必須分別記錄；同一 DB 不代表同一 decision-time snapshot。

## ML COMPATIBILITY REQUIREMENTS

`ML_COMPATIBILITY_RISK: CRITICAL`。逐欄比較 source version、available-at、candidate IDs、feature values／order／dtype／missingness、model identity、projection 與 receipt。必測 source-update barrier、future rows、active-model race、quarantine、loader rejection、receipt failure。舊 artifact 仍由原 schema/provider 解讀，不能重新 hash 偽造相容。

## PERSISTENCE COMPATIBILITY REQUIREMENTS

既有 model artifact、checkpoint、receipt schema／identity 與 recommendation annotation 可解碼；新增 preparation metadata 必須走 canonical execution codec 的 versioned optional contract，不得讓 repository 重算或補寫。

## TEST REQUIREMENTS

執行 ML snapshot provider、historical feature builder、safe loader、calibration integration、model lifecycle／checkpoint、receipt 與 direct-boundary guards；新增 frozen input mutation、provider 禁止於 infer 內呼叫、model/lineage 深層 alias 隔離與 A/B interleave、更新競爭及 projection byte／value parity 測試。Runtime capability 必須由同次 invocation 透過既有安全 loader 從已驗證 artifact 載入；不可使用 consumer cache、外部 model instance 或共享巢狀 mutable alias。若採 clone，須另有 alias 與 ABI 證據。

## ACCEPTANCE CRITERIA

inference projector 的唯一 runtime input 是版本化 `PreparedMLRuntimeInputV1`，其中的 `PreparedMLInput.v1` 保持純身分／reference 契約；projector 執行中無 DB／HTTP／filesystem lookup。Model/lineage capability 不暴露可寫欄位、不跨 invocation 保留或序列化，且通過深層 alias 隔離與 A/B interleave 測試。所有 ML parity oracle 通過；TMP-ML-01 legacy preparation branch 已刪；永久 compatibility readers 與 aliases 仍可載入歷史 artifact。

## EXPECTED DELIVERABLES

explicit preparation wiring、frozen input contract 的 production use、focused ML compatibility tests、TMP-ML-01 retirement evidence 與 before／after identity report。

## POST-TASK REPORT REQUIREMENTS

列出所有 input fields、版本、resolve 時點、模型／feature／receipt hashes、測試 artifacts、已保留永久相容項目，以及任何未能證明相容的差異。

## ROLLBACK / FAILURE CONDITIONS

任一 bytes、dtype、order、missing、identity、timing、projection、receipt 或 fallback 差異都停止 cutover，切回單一 TMP-ML-01 分支並記錄 blocker；不得修改 hash、fixture 或 tolerance 來使測試通過。
