## IMPLEMENTATION OBJECTIVE

app preparation 組成版本化 `PreparedMLRuntimeInputV1`，作為 inference projector 唯一 runtime 參數。其 identity 為 tagged union：strict `PreparedMLInput.v1`、明示 UNKNOWN 且維持既有 shadow eligibility 的 `LegacyShadowIdentityV1`，或同次明確 `rule_only`／無 model 的 `NoModelShadowIdentityV1`；strict V1 ABI 不變。NoModel variant 保存同次 reload 的 blocker、pointer status 與實際 pointer bytes（若存在），不構造 ModelBinding、model-resolution facts 或 loaded class。Runtime input 使用同次 ordered candidate/features/schema/hash facts、service 原 decision clock、ML custody reference、private invocation capability，及可選 `VerifiedSourceContractEvidenceV1`。Legacy release/class 欄位不從 model/candidate ID、run ID、artifact hash 或 runtime Python class 推導。infer 不再自行查資料、模型、pointer 或 source-contract path。

七 gate 使用目前已列的有限 runtime profile 與實際 production model graph 驗收：Windows／CPython 3.11.9／NumPy 2.3.5／scikit-learn 1.8.0／SciPy 1.16.3／joblib 1.5.2（NP2），以及 Windows／CPython 3.11.9／NumPy 1.26.4／scikit-learn 1.8.0／SciPy 1.16.3／joblib 1.5.2（NP1）；兩者皆要求 exact `RecommendationCalibrationConsumer`、`SafeShadowModelArtifactLoader`、default `joblib.load`，及 active/lineage nodes 符合 versioned allowlist。service 對 allowlisted profile與graph現在預設使用 Prepared runtime；capability 未成立時沿用原路徑與可見結果，不以 `None` 新增拒絕或 unavailable。非 production custom/test-injected consumer及未列 tuple沿用永久 public `project()`／`project_many()` 相容入口。Root 已接受有限 production caller/profile 的 runtime、typed post-calibration handoff 與七 gate 證據，`TMP-ML-01` 定義的正常 `RecommendationService` 遷移條件已 `CLOSED`；C2 為 `ACCEPTED_WITH_NAMED_QA_BASELINE`，細節見 implementation report checkpoint。這不代表未受驗任意 profile、custom caller 或 model graph 已驗證，也不擴大支援集合。

## ML COMPATIBILITY REQUIREMENTS

`ML_COMPATIBILITY_RISK: CRITICAL`。逐欄比較 source version、available-at、candidate IDs、feature values／order／dtype／missingness、strict/legacy model identity、projection 與 receipt。必測 source-update barrier、future rows、active-model race、quarantine、loader rejection、configured source-contract mismatch、receipt failure。舊 artifact 仍由原 schema/provider 解讀，不能重新 hash 偽造相容或要求批次補建歷史 producer 欄位。

## PERSISTENCE COMPATIBILITY REQUIREMENTS

既有 model artifact、checkpoint、receipt schema／identity 與 recommendation annotation 可解碼；新增 preparation metadata 必須走 canonical execution codec 的 versioned optional contract，不得讓 repository 重算或補寫。

## TEST REQUIREMENTS

執行 ML snapshot provider、historical feature builder、safe loader、calibration integration、model lifecycle／checkpoint、receipt 與 direct-boundary guards；新增 strict/legacy/no-model identity mutation、configured source-contract evidence bytes/field parity、projector no-I/O、model/lineage 深層 alias 隔離、A/B interleave、更新競爭及 projection/receipt byte parity 測試。Runtime capability 必須由同次 invocation 透過既有安全 loader 從已驗證 artifact 載入；不可使用 consumer cache、外部 model instance 或共享巢狀 mutable alias。NP1與NP2各自獨立驗收；未列 tuple或model graph在capability `None`時必須保留既有合法projection，不能把 `None` 當 parity 或新拒絕理由。若採 clone，須另有 alias 與 ABI 證據。

## ACCEPTANCE CRITERIA

inference projector 的唯一 runtime input 為版本化 `PreparedMLRuntimeInputV1`；strict `PreparedMLInput.v1` ABI 不變，legacy 欄位明確維持 `None`／`UNKNOWN`，且只有基線已允許的 shadow case 可走 legacy variant。Projector 執行中無 DB／HTTP／filesystem lookup；configured source-contract 用同次 immutable evidence 純驗證，既有 provenance/receipt bytes 不變。Model/lineage capability 不暴露可寫欄位、不跨 invocation 保留或序列化，且已通過有限 NP1／NP2 supported graph 的深層 alias 隔離、A/B interleave、projector no-I/O、sparse feature parity、typed receipt handoff 與完整 receipt bytes parity gates。Root 接受此有限正常 production service migration，`TMP-ML-01` 的此項遷移條件已 `CLOSED`；永久 public compatibility APIs、未列 tuple、任意 graph、custom consumer 與 status-only readers 保留相容行為，不宣稱它們已驗證。C2 是 `ACCEPTED_WITH_NAMED_QA_BASELINE`，詳見 implementation report current checkpoint；這不是全 profiles 或 production promotion 結論。
