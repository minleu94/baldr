# R029 — 退休 legacy runtime paths 與 temporary components

## TASK CONTEXT

主要 caller、replay、factor、strategy 與 ML preparation 切換後，舊 `last_*`、list façade、保存／replay bridges、重複 rule body、DTO imports 與 re-exports 仍可能遮蔽雙路徑。app private source-orchestration body 與 execution capture 不因 `TMP-REC-01` 窄 bridge closure 而自動成為刪除目標；clocks/error/progress 由 app execution telemetry 邊界列管，ML availability/projection receipt 由 `TMP-ML-01`／R026 列管。

## WHY THIS TASK EXISTS

架構只有在舊 runtime path 依四步刪除 gate 退場後才有單一 owner；永久 decoder 與已證實的 serialized class alias 則必須保留。

- [FINAL_TARGET_ARCHITECTURE 的 compatibility boundary](../FINAL_TARGET_ARCHITECTURE.md)

## DEPENDENCIES

R013–R016、R020–R026；R027 gate 必須已有 verdict，R028 已完成或 TMP-ML-02 仍明示列管。

## ALLOWED SCOPE

刪除已無 caller 的 canonical rule `last_*` reconstruction、重複 pure rule body、list/save/replay bridges、舊 DTO import wrappers、strategy re-export、臨時 test selection 與其 dead tests；保留仍提供 source orchestration 的 app private body。clocks/error/progress capture 由 app execution telemetry 邊界管理；ML availability/projection receipt capture 由 `TMP-ML-01`／R026 管理，各自達成遷移條件後再處理。更新 retirement ledger、guards 與支援期證據。

## OUT OF SCOPE

刪除歷史 schema decoder、未知或已證實的 joblib／pickle alias、強迫退休 TMP-ML-02、改推薦／策略／ML 演算法、藉 cleanup 大規模改名或搬檔。

## CURRENT BEHAVIOR TO PRESERVE

所有新 canonical flows、舊 artifact read、公開支援期內契約、UI／CLI 行為、numeric parity、ML ABI、create-only persistence 與 replay policy。

## IMPLEMENTATION OBJECTIVE

依「caller 已遷移、相容驗證完成、direct/dynamic/string/serialized search 為零、relevant tests 通過」逐項退場。`REMOVES_TEMPORARY_COMPONENT: TMP-REC-02, TMP-REC-05, TMP-REC-06, TMP-NUM-01, TMP-STR-01`；`TMP-REC-01` 已由 R019 bounded CLOSED，R029 僅做回歸檢查，不重開整體 body/capture 移除。REC-02 必須分別完成 list/latest-state caller/support exit 與 v1 event/callback sidecar consumer exit，兩條皆完成後才可關閉；永久 historical decoder 不刪。R029 另須明列 `TMP-RGM-01` 的 status/owner，只有在 ledger 所列 caller／support gate 通過後才退役，否則保持具名 compatibility status 與 owner。`TMP-ML-01` 仍 ACTIVE，由 R026 負責 execute MLAvailability／receipt 對 invocation capture／legacy context 的退出證據；TMP-ML-02 只依 R028 或 AB-ML-01 狀態處理。

## ARCHITECTURAL INVARIANTS

INV-01、INV-03、INV-11、INV-14、INV-17。不得存在兩套 evaluator／registry 或重複的內部 DataFrame row-dict engine／bridge、無 owner generic mapping；外層 `RecommendationSnapshotDTO.recommendations` v1 live compatibility projection 與既有 portfolio／factor-manifest consumers 維持。永久 reader 不可成為新 writer fallback。

## ML COMPATIBILITY REQUIREMENTS

保留所有歷史 model／checkpoint readers、必要 class aliases 與 loader rejection policy。每個刪除 symbol 必須由 R006 inventory 證明不在 serialized qualified paths；TMP-ML-02 未解時只能列管，不得假定已完成。

## PERSISTENCE COMPATIBILITY REQUIREMENTS

新舊 JSON／SQLite copy 仍可讀；歷史 decoder 保留；create-only idempotency／conflict 行為不變。刪除 legacy writer 前需確認沒有 scheduler、dynamic caller 或 recovery tool 使用。

## TEST REQUIREMENTS

執行所有 affected UI／CLI／save／replay／strategy／ML loader tests；以 `rg` 與 dependency checks 查 direct、dynamic、string scheduler 與 qualified-name references；對每個 TMP 執行 retirement evidence checklist。

## ACCEPTANCE CRITERIA

canonical rule business result 不再從跨 invocation／latest `last_*` 重建，沒有雙 engine／registry 或重複的內部 DataFrame row-dict bridge；必要的 clocks/error/progress 由 app execution telemetry 邊界列管，ML availability/projection receipt 由仍 ACTIVE 的 `TMP-ML-01`／R026 列管，不將這些 capture 誤報成無 I/O。R029 status/owner inventory 必須包含 `TMP-RGM-01`，依 caller／support gate 決定退役或具名保留；各 TMP 均有 `closed`、`permanent compatibility` 或 `blocked with owner` 狀態；舊 artifacts 仍 load；工作區無廣泛 allowlist。

## Scope clarification（2026-09-24）

REC-01 原始 retirement list 曾包含 private body 與整體 capture；R019 C3B/C3C2/C3C3 僅關閉 legacy state/matrix→canonical rule bridge。故 REC-01 從 R029 的未來移除清單移出，保留為已關閉狀態的 regression guard；source orchestration 與 execution clocks/error/progress capture 不因此被宣告移除，後者由 app execution telemetry 邊界列管；ML availability/projection receipt capture 由 `TMP-ML-01`／R026 列管。REC-02 擴為 list/latest-state 與 v1 event/callback sidecar 的聯合 ACTIVE 項，兩個退出子條件需各自通過。
