# R030 — architecture guards 與三項 extensibility acceptance

## TASK CONTEXT

完成 runtime 收口後，需要以窄而可診斷的 checks 防止逆向 import、重複 mapping、hidden state、codec 分支爆炸與舊 ML identity 被後續變更破壞。

## WHY THIS TASK EXISTS

FINAL 架構要求以三個小型推演證明新增 confidence、strategy 與 technical feature 的變更局部性，而不是只靠目錄形狀宣稱可擴充。

## DEPENDENCIES

R029。

## ALLOWED SCOPE

新增或收窄 `scripts/check_*boundary.py`、dependency/schema guard tests，以及三組 synthetic acceptance fixtures；可修正 guard 自身的 false positive，但不發布產品功能。

## OUT OF SCOPE

真正新增 production confidence 欄、strategy、technical feature 或模型；廣泛 allowlist；以 snapshot 整個 source tree 取代具體契約 assertion。

## CURRENT BEHAVIOR TO PRESERVE

現有 imports、codec round-trip、save/replay、strategy registry、ML v1 schema／hash 與 UI presenter 行為。既有 guard violation 必須具名列 baseline owner，不能靜默消失。

## IMPLEMENTATION OBJECTIVE

建立能對刻意違規失敗的窄 guards，並完成三項推演：confidence 只改 contract revision＋calculator＋presenter；新 strategy 經 registry；新 technical feature 不改舊 ML v1／hash。

## ARCHITECTURAL INVARIANTS

INV-02、INV-03、INV-11、INV-14、INV-16、INV-17。Guard 必須描述禁止的 edge／mapping／state，而不是依賴不穩定全文比對。

## ML COMPATIBILITY REQUIREMENTS

technical feature fixture 必須同時證明新版本可擴充且舊 ML v1 feature names／order／dtype／missing／hash 完全不變；現有四項 direct-boundary violations 需保留具名 baseline 或已由前置任務實際修正，不得宣稱原本全綠。

## PERSISTENCE COMPATIBILITY REQUIREMENTS

confidence fixture 應由 schema-driven codec 自動處理 typed optional scalar，且 save／replay body 不因欄位名稱新增分支；舊 schema revision 仍可 decode。

## TEST REQUIREMENTS

每個 guard 都需正例與 negative fixture；刻意加入 decision→app import、duplicate row map、business `last_*`、unknown codec type、registry bypass 與 ML v1 mutation 時必須失敗。三項 extensibility acceptance 全部獨立可重跑。

## ACCEPTANCE CRITERIA

Guards 對目標違規有明確錯誤與 owner，無 broad allowlist；三項推演均證明預期局部性；舊 artifacts、replay、strategy 與 ML v1 fixture 均維持相容。

## EXPECTED DELIVERABLES

Boundary scripts／tests、negative fixtures、三份 acceptance evidence、known-baseline ledger 與維護說明。

## POST-TASK REPORT REQUIREMENTS

列出每個 guard 的 protected invariant、正／負例、已知 baseline owner、三項推演實際變更面與未被涵蓋的風險。

## ROLLBACK / FAILURE CONDITIONS

Guard 若需廣泛豁免、對無關格式頻繁誤報、無法抓到 negative fixture 或推演需修改 central codec／evaluator，則回滾該 guard 並回報前置架構未達標，不得降低 assertion。
