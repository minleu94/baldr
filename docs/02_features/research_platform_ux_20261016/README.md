# Baldr：先看懂結果，再深入研究

2026-10-15｜依使用者最新定位及三個參考頁修訂。這是產品分析與改善提案，未修改產品程式或正式 Roadmap。

**Baldr 的目標是讓懂股票基本概念的人，快速掌握市場、找到候選、評估報酬與風險，並保存及回顧自己的判斷。新手友善是整體介面的品質要求；完整的選股、研究、持倉與紀錄能力仍是核心。**

前版把主要對象收窄為零基礎新手，因而過度強調教學、首次筆記與概念階梯。本版依使用者澄清撤回這個排序，也撤回「進階策略對主要使用者價值較低」的推論。首次操作應直接得到有用的研究結果，理解說明按需要提供。

## 希望完成後是什麼樣子

打開程式，先看到市場重點、產業強弱、可研究的股票，以及自己需要回顧的事項。選一檔股票，就在同一個視野看見走勢、支持理由、主要疑點、可用的績效或模型結果。需要查證時，直接到既有研究頁；保存後，下次能接續當時的判斷。

**第一層提供足夠資訊完成初步判讀；第二層提供研究依據；第三層提供精確核驗。** 不能讓第一層只剩標題和「查看詳情」，也不能讓每個重要答案都要連點數頁才找得到。

| 頁面 | 一開始就應回答 | 可深入的既有能力 |
|---|---|---|
| 今日總覽 | 大盤怎樣？哪些產業在變？哪些候選值得看？我的研究有何待辦？ | 市場、產業、選股、持倉、原研究 |
| 產業探索 | 哪些產業較強／較弱？哪些成員帶動？產業與題材有何不同？ | 同業比較、成員個股、分類與資料依據 |
| 選股 | 為何入選？依什麼排序？支持與反證是什麼？ | 條件、策略版本、比較、歷史成果 |
| 個股研究 | 這家公司目前好在哪、疑點在哪？走勢和條件是否相符？ | 價量、技術、基本面、籌碼、策略與原始證據 |
| 我的研究與持倉 | 上次為什麼關注？之後變了什麼？哪些部位需要檢視？ | 原收藏、研究紀錄、指定帳本與回顧 |

這是資訊職責，不要求新增五個工作區。先在原首頁、產業與個股頁整理資訊，再驗證導航是否需要調整。

## 三個參考頁帶來的方向

- [每日選股](https://www.dannyquant.com/signal-lottery-preview)：先有預設結果，再提供條件與排序、績效入口。借鑑結果先行和可比較的卡片結構；本次只檢視公開訪客內容，未核其策略效果。
- [產業地圖](https://www.dannyquant.com/industry-map)：每日重點、漲跌分布、產業強弱、法人動向、題材和公司入口分區並列。借鑑高資訊密度下仍有清楚主次，讓人先掌握整體再選研究方向。
- [個股研究](https://www.dannyquant.com/stock)：公開說明將走勢、技術指標與策略追蹤放在同頁。本次訪客畫面需要進階會員，未檢視受限內頁；「Baldr 個股一頁整合」是依使用者偏好與本地能力提出的設計，不能宣稱已完整複核對方實作。

採用資訊組織與互動原則，保留 Baldr 自己的資料、算法、來源核驗及紀錄能力。參考網站的訊號分數、分類和績效不直接變成 Baldr 的證據。新產業鏈、題材關聯或新聞情緒若超出現有來源，另立有來源的工作項。

## 假設補完全部完成，仍有哪些問題要驗證

原計畫已承諾來源連續、保存重開、正常頁、同版交付、非技術者理解與效能驗收。這些應在「補完完成」時成立，不能重列成完成後必然殘留的缺陷。[原首屏與完整旅程](../../../docs/superpowers/plans/baldr_product_completion_plan_20261006.md:254)

真正還要驗證的是下列產品結果；目前屬有證據支持的風險假說，尚非本次真人觀察：

| 可能仍不順暢之處 | 為什麼會妨礙使用 | 改善方向 |
|---|---|---|
| 卡片只有入口、筆數或系統狀態 | 功能都存在，使用者仍要自己拼答案 | 每卡給一句判讀、關鍵圖形／數值、主要疑點和明確動作 |
| 同一檔的市場、產業、策略、模型結果分散 | 切換時難同時比較，容易忘記原問題 | 個股摘要並列支持／反證；常用資訊同頁，來源可展開 |
| 用紅綠燈或總分代替股票優劣 | 不知分數依據，也看不見訊號矛盾 | 分列趨勢、基本面、籌碼與風險；綜合判讀須有定義規則 |
| 報酬、勝率、排名和模擬結果太像 | 容易把研究估計讀成將來一定能賺多少 | 數字旁標種類、期間、成本；報酬與風險並列 |
| 新增圖卡或跨頁整合可能破壞原返回契約 | 屬後續變更的回歸風險，不能接受為補完殘留 | 驗同一股票、來源、日期、條件及帳本一路傳遞 |
| 每天要自行排查資料日期與更新 | 日常使用被資料維護打斷 | 首頁摘要可用範圍；接既有更新入口，處理中斷與久未更新 |
| 原研究已完整保存，但使用者仍難找回當時問題 | 保存正確與研究能累積是兩個不同驗收面向 | 清楚題名與可選理由；回顧時並列當時和現在 |
| 首次設定、移機或新版仍需工程知識 | 進不了產品，圖卡再好也沒有用 | 圖形化設定、可核版本、同版指南與恢復流程，獨立驗證 |

限制資訊應短而準確，如「盤後資料・截至 10/15」「歷史模擬・已扣成本」「基本面缺本期資料」。詳細核驗按需展開；影響判讀的缺件、估計種類和期限不能藏起來。

## 建議的改進順序

1. **先定第一屏應交付的答案。** 用首頁、產業、個股原型驗證資訊主次；一般股票使用者、深入研究者和新手分組看同一套頁面。現在即可測，不等補完結束。
2. **完成一條圖卡到紀錄的完整路徑。** 市場摘要→指定候選→個股優缺點→收藏／理由→返回及隔次重開。同期改善日期與更新入口。
3. **接通產業探索與成果比較。** 成員、強弱、同業比較、策略績效及合格模型結果沿原服務前移；每項數字可直接追到原結果。
4. **逐步擴充策略與日常回顧。** VCP、形態、族群與共振保留原承諾，接入共用旅程；再改善持倉變化、紀錄回訪及提醒去重。
5. **持續驗證交付與資料維護。** 首次設定、離線、久未更新、移機及升級各有獨立情境；不以本機受控試用當作可攜版完成。

這是提案排序，未另建競爭進度框架。既有工作卡補「第一屏回答什麼、可做什麼、如何回到原研究」即可。用詞修正伴隨同旅程交付，不能代替資料投影與精確路由。

## 對外部複審的採納與修正

採納：先確認動機、提早真人試用、重視每日資料生命週期、減少工程詞、先結論再證據，以及按風險安排新增驗收。撤回零基礎教學優先與強制概念階梯；研究紀錄重要，但不要求先寫筆記才能得到價值。

兩項事實需修正：已有快速／安全手動更新，不能說每日更新只有 Windows 排程；首次設定與資料狀態也不是原計畫完全未涉及，但完整設定／恢復體驗仍需具體驗證。[現行更新](../../../docs/07_guides/manuals/DATA_AND_MARKET_RESEARCH.md:5)、[首次設定](../../../docs/07_guides/PORTABLE_WINDOWS.md:5)

71 是四股舊資料的固定本機候選，可安排受控試用，不能當跨機安裝包或全市場／模型能力的證明。已唯讀確認 EXE 為 NotSigned，未實測 SmartScreen／防毒攔截；簽章也不保證不出現信譽警告。[71 範圍](../../../docs/07_guides/TRIAL_VERSION_GUIDE.md:9)、[簽章記錄](CANDIDATE_SIGNATURE_AUDIT.json)、[Microsoft 說明](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)

驗收可按風險增加不同案例；現行 UI 變更共同檢查仍維持。期間、成本、績效含義的文字涉及金融語意，不能視為單純文案。先合併相依修改、重用仍適用的證據，減少無效重跑。[共同規範](../../../docs/agents/shared_context.md:20)

## 如何知道真的變好

讓人不看手冊就能說出市場重點、關注理由、主要疑點、數字屬於估計還是成果，以及下一步。接著能比較、查證、返回、保存並找回當時判斷。[試用腳本](USER_JOURNEY_VALIDATION.md)

保留原 3–5 位非技術者、30 秒判讀與 2 分鐘進個股收藏標準；前期 2–3 人試用用來找問題，不能代替正式接受。記求助、開錯來源、返回丟失及成果誤讀，不只問畫面好不好看。[原真人驗收](../../../docs/superpowers/plans/baldr_product_completion_plan_20261006.md:898)

建議正式產品定位採用開頭表述，以「清楚的第一屏＋完整研究深度＋連續判斷紀錄」驗收。這次只更新分析提案，正式 Roadmap、程式及資料來源資格未變更。
