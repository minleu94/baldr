## 判讀界線

本包分開記錄 consumer／收據明示的 `decision_date` / `as_of`（決策或查詢日期），以及 `market_date` / `source_date` / 來源交易日（資料所屬交易日）；兩者不能合併。來源表的 `as_of_date` 依該來源欄位定義處理，例如月營收樣本是期間末日。`observed_at` 是系統看見資料的時間；`available_at` / `source_available_at` 是欄位有提供時記錄的可用時間。精確 decision instant / cutoff 若未提供就標 unknown。遇到來源沒有記錄發布或可用時間時，不由檔案 mtime 推算資料日期。

## UX18 前要補的來源缺口

1. 逐 consumer 量正式 D 的 universe 分母、代碼覆蓋、重複／缺漏、近端可用 session 與每類來源的 per-stock 深度；將一檔或少量 fixture 證據與市場覆蓋分開。
2. 對每個欄位確認官方發布時間、系統首次觀測時間、消費者 decision cutoff，並界定其缺值或 degraded/conflict 的處理；確認 20/60 只是既有參數／指標窗或 UX 方法所需暖機，不自行認定最低門檻。
3. 驗公司分類與產業／市場 benchmark 的歷史有效日期、成分、來源與可用時間，禁止用 current map 回填 PIT。
4. 完成 current fundamentals 的 period/basis/unit 換算、原始公告與 comparator lineage，以及歷史 provider 的可用日驗證；分開 current-only 與正式 PIT。
5. 對 Phase3C 補 source/version pin、逐股納入、availability/publication、品質及 units 證據；解決 current revision 與候選 raw-capture 的完整 provenance。對 chips 補分點母體／排名分母與當日 source cutoff。
6. ML 要列明 pinned feature registry 的全部字段、各字段 PIT／warm-up、標籤 horizon/maturity、正式 universe 與模型產物；另確定 benchmark 身分／窗口與成本目標。沒有此證據不建立新方法、不做暖機結論或採用資格判定。

本矩陣只交付 UX16 的來源子集與下一包依賴；未建立新 ranking、factor 或 benchmark，也未啟動 UX18。
