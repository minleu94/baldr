# 批次回測逐股保存規則來源

此頁補充原[操作手冊](../APPLICATION_MANUAL.md)的「策略回測」章節。目前指定[日常研究115](../../../output/trial/Baldr-Daily-Research-115/TRIAL_GUIDE.md)已驗正常Windows EXE的逐股保存、原規則卡、返回及另一程序讀回，並納入批次通用比較拒錯；操作條件見該指南。112原保存旅程及原109包仍保留，不能套用新版拒錯狀態改寫舊版驗收。

在「策略回測」選批次單股或固定籃子研究模式，選股票、原策略版本、日期及成本後執行。排行榜每一列是**獨立股票、獨立本金**的結果，不是共用現金組合。要回看某列，先看 `RunID`：有值才代表本次研究 Registry 保存完成；空白時看「失敗原因」，不能用舊式 run 檔冒充可重開的研究版本。

在「研究歷史查找」選該列的精確 `batch-backtest:<RunID>`，讀回結果與「已保存策略版本」規則卡。新保存的固定策略逐股結果會保留當次輸入資料指紋、參數契約、執行器及撮合設定。若原輸入與保存設定不符，規則卡會拒絕綁定來源；它不會拿目前畫面設定補舊 run。`source_ref_only` 只表示規則來源可追，不表示歷史資料具 PIT 資格或策略績效可採認。零交易列可以保存作診斷，不能當成有效策略。

舊式單獨保存的 run、未走固定策略來源封存器的舊批次結果，以及資料來源／成本／幣別／歷史 PIT 未通過的結果，仍按原限制顯示。布林／W 底在隔離行情的四筆逐股保存、固定 EXE 主視窗的研究歷史規則卡與另一 EXE 程序唯讀重開已有受控 QA；真人手勢與不同 DPI 尚待試用回報。完整雙策略排名、Walk-forward、SOP 與正式交易資格也未由此增量取得。

115的「研究 Registry → 比較選中」對批次逐股／固定籃子逐股run加上拒比守衛：即使資料指紋、撮合與sizing相同，也明示缺來源、幣別、成本與歷史PIT資格，清空績效、benchmark及標準化權益。較窄視窗先按「查看實驗結果」，切到Registry後向下捲動查看原因；仍可由「找已保存結果」分別開原列。正常EXE父／新程序及訊息位於捲動可視區的證據見[Increment115 QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md#increment115-fixed-trial-delivery)。112不含此修正，不把112的「保存條件相同」解讀為完整雙策略績效資格。
