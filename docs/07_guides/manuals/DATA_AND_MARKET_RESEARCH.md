# 資料與市場研究

本手冊說明「數據更新」與「市場探索」的日常使用。開始前先確認程式使用自己的 `DATA_ROOT`、`OUTPUT_ROOT`；兩個路徑分開設定。若畫面顯示空資料或舊日期，先檢查根目錄、來源日期與狀態，再決定是否更新。

具名營益固定版本由「個股研究」讀取，不由本頁重新抓取。原2330 v1保持；開發來源另有2317／2330／2454的2026-H1五欄版本，須明選對應schema、目錄及雙SHA，並等實際成功批次台北可用小時。2382文件驗證頁與前期缺件各自隔離，不把缺值補零；設定、口徑及限制見[具名營益指南](RECOMMENDATION_AND_RESEARCH_LAB.md#具名營益固定版本研究)。

## 檢查與更新資料

1. 開啟「數據更新」，按「檢查數據狀態」。這一步讀取來源狀態，不會替缺件補值。
2. 檢查股價、大盤、產業、券商分點及技術指標的資料日、筆數、缺件和 warnings。`current`、`expected_wait`、`stale`、`failed`、`partial`、`not_applicable`、`unknown` 含義不同；不要只看綠色狀態或最新日期。
3. 選擇更新範圍。快速更新會補近期日檔並增量同步 SQLite，預設以結束日前最近 10 個工作日為範圍，跳過大型合併檔重寫。安全更新會依選定範圍補日檔、重建每日股價與券商分點合併檔，再同步 SQLite。
4. 按照頁面提供的日期和來源啟動更新；若結果標為部分、失敗或取消，先查看錯誤與實際完成日期，再決定是否重試。
5. 更新完成後再按「檢查數據狀態」，確認同一資料根和 SQLite 的日期／涵蓋情況，再進入市場研究。

快速更新適合日常盤後補齊，並不等於完整重建 CSV；若離上次更新超過近期窗口，使用個別來源日期範圍或安全更新。來源沒有官方資料的日期可能合法略過；HTTP、schema、parser、mapping 或 SQLite transaction 失敗要保留為失敗，不能把缺資料當零。

### 中斷與資料安全

- 更新取消是合作式停止；已安全完成的部分可能留下。取消狀態不是全範圍更新成功。完成後重新檢查資料狀態。
- 唯讀 status check 不會下載資料；unknown 或 receipt 不匹配時，先按目前來源流程重查，不手改日期、時鐘、hash 或 receipt。
- SQLite 以本次驗證的 CSV 來源更新；不得反向覆蓋 raw CSV。不要刪除既有資料庫、WAL／SHM、checkpoint 或手動改表。
- 月營收／財報候選資料不等於正式 availability mapping。修復、mapping 或歷史 backfill 須依[每日資料更新指南](../../03_data/daily_data_update_guide.md)的 preview、備份和明確 apply 步驟。
- 若狀態顯示 freshness unknown、stale 或 partial，先查看資料根、實際交易日、來源診斷及同一發布週期的 receipt，再重試。不要用 `MAX(date)`、本機星期幾或目前電腦日期猜資料新鮮度。

## 市場探索

### 單日官方注意公告（後續開發分支）

個股研究報告的「TWSE 官方注意公告」獨立顯示選定版本的公告日、原因、原累計次數、收盤價與本益比字串，並列出來源、台北可用小時及 manifest／receipt 身份。這是公告原件的研究註記；「注意」與「處置」分開，不能用它推論交易限制、連續注意日數或交易建議。來源涵蓋上市有價證券，可能包括權證；筆數不是股票母體或真N。

此入口屬後續開發分支，固定 `9fa4518c` 試用包不變。來源準備者先用 `scripts/save_official_attention_snapshot.py` 明選已保存的完整單日 attempt、原 HTTP 收據 SHA、公告日、三份官方查詢契約原件及全新輸出目錄；參數分別為 `--attempt-directory`、`--http-receipt-sha256`、`--query-date`、`--notice-html`、`--web-report-js`、`--main-js`、`--output-directory`。所有路徑須明示絕對路徑，輸出不得位於正式或私人資料根；命令只讀原件並另存候選，不會下載或更新資料庫。原件缺完整 EOF、逾時、schema 變動或收據不符時拒絕；不可手補原收據。

在啟動後續開發版前，設定 `OFFICIAL_ATTENTION_SNAPSHOT_DIRECTORY`、`OFFICIAL_ATTENTION_MANIFEST_SHA256`、`OFFICIAL_ATTENTION_RECEIPT_SHA256`，三者必須指向同一已保存版本。未設定、少一值或錯 SHA，只使此公告區顯示具名不可用原因。程式不搜尋 latest；更正版本另存後，明確改選三值並重新啟動。從「觀察清單 → 查看選中個股研究報告」開啟股票，可閱讀公告區，再按「返回來源清單」回到原清單；重啟後仍讀相同固定版本。

公告只有基準日期，沒有發布時分時，以實際成功保存批次完成時間向上取整到台北小時，basis 為 `successful_batch_completion_fallback`。本輪 2026/10/15 的真公告保存於台北 10/16 05:26，最早 06:00 可讀；該時間之前顯示不可用是預期行為，不能改系統時間或指定未來 cutoff。歷史報告也不得使用當時尚不可得的版本。此批不授歷史 PIT、TPEx、來源用途或正式策略資格。

有列時看原日期與原因；空列只表示「此 TWSE 公告日查無此代碼；未判定其他市場」。來源錯誤、pending、取消、版本遭修改或時鐘不合格均保持未知，不能當作沒有公告。收盤價與本益比原值不回流金融計算；`-----` 等缺值原文不補零。

### 每日研究條件與具名研究母體

要閱讀已發布的具名研究快照，從「市場探索 → 研究母體盤勢」查看來源、決策日、方法與符合／不符合／未知分母；這是指定 cohort 的研究觀察，不是全市場統計。按「開啟同來源研究名單／明確更新」可進入「推薦分析 → 每日研究條件」，沿同一已核驗來源看名單與個股。若來源尚未發布，先確認來源清單與研究根；不要用候選列或最新行情代替原快照。

在「每日研究條件」頁先核對研究 cohort、基準日期和 `Asia/Taipei` 截止時間。股票代碼最多 16 檔；固定條件可選收盤高於 MA20、MA60，或選擇 AND／OR；只有畫面提供時才使用「收盤價高於布林上軌（30）」，它只讀原保存證據，參數 lineage 未核驗，不能視為已接受的策略或 PIT 證據。套用下拉預設必須按「套用預設」才會改變查詢條件。

- 初次開頁會唯讀核對已發布快照；「重讀已發布快照」仍是唯讀。只有明確按「更新研究快照」才啟動有界研究工作，不會因排序、篩選或切頁產生資料。
- 更新完成後先看來源身份、資料日、名單母體與三態計數，再用「全部／符合／不符合／未知」控制可見列。這些篩選只改畫面；母體分母及三態計數仍以完整快照為準。未知不等於不符合，也不代表未入選。
- 依表格欄位排序只改顯示順序；原始名次只有來源真的提供時才可用。選取股票可「開啟選中個股研究報告」，或按「收藏此研究」保存來源與條件脈絡。收藏重開仍核驗原來源，不自動替換成最新研究。
- 「取消更新」是合作式取消：等待已啟動讀取安全返回，未完成結果不會當成有效快照。若狀態顯示來源變更、身份不符或失敗，保留診斷並重讀同一保存版本；不要手動改日期、hash 或查詢身份。

### 已保存來源與完整母體研究

「推薦分析 → 每日研究條件」頁也包含已保存的市場／技術研究與完整母體（Union）檢視。先按該頁的來源版本控制明確選取保存版本並核驗；僅看到 catalog 候選或按「更新來源清單」並不代表內容已驗證。按「套用全域查詢」後，先看來源 pins、完整母體數、資料日與 warnings，再閱讀表格。技術 Union 的空股票代碼篩選表示使用整個已保存母體；輸入代碼只縮小該母體。全域篩選與排序先作用於完整查詢，再依每頁 25、50、100 或 256 列分頁。這些列數是頁面顯示上限，不是來源母體大小。

選取原列後可讀原保存個股證據、建立同來源比較，或準備研究收藏。技術 Union 比較籃需 2–256 檔；官方市場與技術條件頁的比較籃是 2–5 檔，依頁面顯示的範圍操作。返回來源頁後，若原查詢、頁面或選取身份已變，先依原來源重新核驗，不把不同版本的列混在一起。收藏用來精確重開原來源、query 與選取狀態，不會把當期研究升成歷史 PIT 或正式訊號。

瀏覽、篩選、比較和重開收藏是讀取流程；「產製技術與官方來源研究」是另一項明示的研究工作，不等同重讀來源清單。只有在確定要產生該研究時才使用它。來源不可用、頁面明示只讀外部保存來源、或核驗失敗時，保留目前畫面與原因，勿另指定最新來源繞過錯誤。此類頁面的精確來源身份、保存與讀回契約見[目前資料儲存架構](../../01_architecture/current/data_storage_runtime.md)；功能是否接線及整體驗收仍以[目前狀態快照](../../00_core/PROJECT_SNAPSHOT.md)為準。

### 官方處置原件重讀（後續開發分支）

在「推薦分析 → 官方市場／處置研究」明選已保存來源，核對來源身份與原觀測日，選股後開啟原處置明細，再用頁面「返回」回原名單；重啟程式仍明選同一保存版本。Increment46 新來源可讀 TWSE 官方英文公告原件的理由、措施、內容及有效期間；目前只驗 1709、2466、2492 的正常畫面與新程序，同輪行情為四股合成測試，固定9fa試用包尚未包含此修正。

舊 v2 保存來源保持原讀法；若原英文格式顯示未確認，需要沿原 immutable capture 另產新版研究來源，不編輯舊 pin／raw 或以最新版本替代原收藏。畫面處置狀態相對原觀測日，不代表今日狀態；無匹配、來源缺件或錯誤維持未知。官方發布時分與 HTTP 完整證據缺件不補造，仍不可用於歷史 PIT、正式訊號或交易。終止公文會核實際終止日，停止交易不等於終止；若顯示 `market_assignment_termination_source_evidence_mismatch`，保留診斷，勿手改日期、跳過核驗或重抓同一原件。

### 市場總覽與 Regime

進入「市場探索 → 市場總覽」，按「更新決策摘要」讀取同一個市場總覽。先看決策日、行情資料日、quality、warnings 和來源，再看市場狀態、強弱、產業、候選與持倉提示。Regime 是目前資料對既有規則的分類，不是未來預測；規則匹配度也不是勝率。

資料日 fallback、unknown、缺來源或已過期都要留在判讀中。空的待判讀佇列不代表沒有風險、Gate 已通過或可以交易。Daily Decision Desk 只提供已保存來源的唯讀摘要，不能以刷新畫面觸發資料更新或策略執行。

### 個股與產業強弱

在強弱個股頁選「本日」或「本周」，首次按「載入數據」，需要重讀時按「刷新」。先確認狀態列中的有效資料日與筆數，再選股票開啟個股研究。強勢排名不等於追價建議，弱勢排名不等於做空或立即賣出。

在強弱產業頁先核對 benchmark、資料涵蓋與 quality，再選取產業並明確選一檔代表股，按「開啟所選代表股研究」。市場當期的 industry mapping 可能標示 `current_research_only` 或 `historical_pit_eligible=false`；這類列只能作當期研究，不能當作歷史成分證據。

### 主力流向

1. 選擇日線、週線或月線，再選圖表類型與主表顯示範圍。
2. 按「開始掃描」，在主表選股票，閱讀右側分數、集中度、語意狀態與分點明細。
3. 有需要時雙擊分點名稱，切至「分點進出追蹤」查看該分點的近期股票與張數。

預設 Top／Bottom 50 只限制主表列，摘要仍依全市場掃描結果。資料品質 `observed`、`estimated`、`unavailable` 要分開閱讀；估算股數和缺值不是原始成交量。高檔出貨疑慮或分點集中異常是風險提示，不代表已知主力意圖或交易指令。

## 常見問題

### 單獨保存 TWSE 法人候選

後續開發分支的維運 CLI 可明選 `twse_institutional`，僅取得 TWSE T86 法人資料，不把 TPEx 或信用資料設為同批前置。固定 `9fa4518c` 試用包未包含此增量。由 owner 先核既有 attempts、指定用途及有界取得範圍，再使用原入口，例如：

```powershell
.\.venv\Scripts\python.exe scripts\complete_institutional_credit_flows.py capture --capture-scope twse_institutional --sessions 1 --max-lookback-days 1 --max-attempts 1 --output-root output/flows/twse-only-candidate
```

此命令會連網；本輪只做離線測試，沒有執行真取得。未指定 `--capture-scope` 仍沿原 `legacy_all` 四來源行為。`--sessions` 是要求的 T86 有資料日期數，查找範圍由 `--max-lookback-days` 限制，不能當作兩市場共同交易日或法人連買證據。

完成後核對 manifest／readback 的 `capture_scope`、`totals`、raw hash、解析與 quarantine；TWSE 單來源只列法人總數，未要求信用不是零筆。既有 `rebuild --run-dir <保存目錄>` 只重播原 raw，保留選定範圍與單位，缺分區、重複或範圍遭改會拒絕。失敗時保留該 run／錯誤，不刪原件或自動改抓其他來源。

新取得的完整候選可明確保存成功批次時鐘。先核原 capture 的 `manifest.json` 外部 SHA，再對其絕對 run 目錄使用：

```powershell
.\.venv\Scripts\python.exe scripts\complete_institutional_credit_flows.py seal --run-dir C:\absolute\capture\run --capture-manifest-sha256 <原capture的64字元小寫SHA256>
```

`seal` 不連網或 apply；僅在指定 run 旁 create-only 建立 `daily_snapshot`，輸出其目錄、manifest SHA 與 receipt SHA。原件、原 manifest 與正式資料保持不變。需原 HTTP 完整 EOF、長度、來源／版本、原件明示「單位：股」、官方獨立宣告合計、原 parser 品質與全部 candidate 讀回一致；舊 capture 缺 EOF／原單位／合計欄證據時拒絕，不能手補欄位認證。原件宣告自營商或三大法人合計與分類數字矛盾，會保留原件並拒絕／隔離，不重算後覆寫官方值。失敗保留 pending／failure，修正另存新版本，不覆寫原收據。

1. 開啟「數據更新 → 三大法人」，找到「固定法人批次（TWSE／TPEx OpenAPI，唯讀）」。一般更新動作仍走原流程；此區不觸發下載。
2. 輸入上述 `daily_snapshot` 絕對目錄、manifest／receipt 雙 SHA 及證券代碼，按「開啟指定批次」。每次開啟固定當下截止時間，不搜尋最新版本。
3. 先看雙 SHA、首次保存／批次完成時間、台北可用小時與依據，再看所選代碼逐日的三類買進／賣出／買賣超整數股數。外陸資含外資自營；自營商為自行與避險合計，依原 parser 定義。日期提示保留官方時間原文、台北時間、raw SHA 與版本。
4. 「批次母體筆數」是原報表各日期保存列數合計，可能含 ETF 等非股票證券，不是已核股票 universe、全市場真 N 或選股分母。成功但代碼無匹配列與尚未載入／失敗分開顯示，不補零。

只有基準日期時採成功批次完成的小時依據，不能用舊列級 `available_at` 代替。保存與完整再核驗須在可用小時之前完成；尚未到可用小時、缺原件、SHA／版本錯誤、pending 或來源讀取中變動皆拒絕並清除舊結果。修改輸入或按「取消／清除結果」會清除畫面並合作取消，須等本輪 worker 安全返回才能再讀。切至其他工作區再返回可保留已載入結果；新程序仍需明選同一目錄與雙 SHA。

### TPEx法人OpenAPI單日版本（後續開發分支）

### 每日快照的時間判讀

日曆原件下載完整與日曆已通過指定用途驗證是兩件事。本次TWSE年度／TPEx月曆已有完整候選原件與解析紀錄，新的批次保存／重開仍在隔離驗證階段；一般更新頁不會因此自動發布或切換日曆。遇到日曆unknown或期間缺件，保留來源與原因；不可把HTTP日期當官方發布時間，或把新抓版本套回較早的歷史決策。

TPEx年度股票日曆另有獨立來源版本，與TWSE年度原件形成具名年度批次，沿原保存與讀回核心及Registry表單使用；兩市場接受紀錄須同屬年度家族。日期覆蓋、完成小時與用途資格分開核對，正式Main尚未配置真接受紀錄。隔離測試的合成時鐘／接受不是官方成功批次或歷史PIT。

研究Registry已提供明示「每日批次」診斷路由，要求指定批次的manifest／成功收據雙SHA與兩市場獨立用途接受紀錄；正常Main／新程序只用合成接受紀錄限定驗證。正式Main尚未配置真接受紀錄，缺件時比較保持停用；這不代表一般更新頁、日常固定下載或正式排程已接新批次。

新快照研究使用固定成功批次保存的版本。官方發布 14:45、批次完成 15:12 時，最早可用小時是台北 16:00；只有資料基準日期而沒有官方小時時，使用成功批次完成小時並保留時間依據。資料期間不等於可用時間；未保存、品質失敗或部分批次不可當成當輪成功。已保存研究重開仍核同一批次／版本，不換成最新檔案。

首次成功保存後已通過指定用途的新快照可作日常研究；更早的歷史用途仍依實際版本證據，不能以今天抓到的旧期資料回填歷史決策。若顯示缺前期、來源／版本／hash 不符或批次隔離，保留具體原因，待取得缺件或完成該批驗證；不手改時間或補 0。完整政策見[每日快照契約](../../03_data/DAILY_SOURCE_SNAPSHOT_CONTRACT.md)，正常 UI／排程接入與真來源是否完成依[本輪 QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md)判讀。

TWSE 月營收 JSON 候選的單位未核時保留原值與具體阻塞，不自動換成新台幣或加入策略。完整保存原件的解析成功，和當輪抓取／發布成功是不同證據；下載不完整的原件仍隔離。這輪新 JSON 契約尚未接入一般更新頁或正式排程。
