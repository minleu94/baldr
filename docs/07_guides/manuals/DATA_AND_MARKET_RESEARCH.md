## 檢查與更新資料

1. 開啟「數據更新」，按「檢查數據狀態」。這一步讀取來源狀態，不會替缺件補值。
2. 檢查股價、大盤、產業、券商分點及技術指標的資料日、筆數、缺件和 warnings。`current`、`expected_wait`、`stale`、`failed`、`partial`、`not_applicable`、`unknown` 含義不同；不要只看綠色狀態或最新日期。
3. 選擇更新範圍。快速更新會補近期日檔並增量同步 SQLite，預設以結束日前最近 10 個工作日為範圍，跳過大型合併檔重寫。安全更新會依選定範圍補日檔、重建每日股價與券商分點合併檔，再同步 SQLite。
4. 按照頁面提供的日期和來源啟動更新；若結果標為部分、失敗或取消，先查看錯誤與實際完成日期，再決定是否重試。
5. 更新完成後再按「檢查數據狀態」，確認同一資料根和 SQLite 的日期／涵蓋情況，再進入市場研究。

快速更新適合日常盤後補齊，並不等於完整重建 CSV；若離上次更新超過近期窗口，使用個別來源日期範圍或安全更新。來源沒有官方資料的日期可能合法略過；HTTP、schema、parser、mapping 或 SQLite transaction 失敗要保留為失敗，不能把缺資料當零。

### 中斷與資料安全

- 更新取消是合作式停止；已安全完成的部分可能留下。取消狀態不是全範圍更新成功。完成後重新檢查資料狀態。
- 唯讀 status check 不會下載資料；unknown 或 receipt 不匹配時，先按目前來源流程重查，不手改日期、時鐘、hash 或 receipt。
- SQLite 以本次驗證的 CSV 來源更新；不得反向覆蓋 raw CSV。不要刪除既有資料庫、WAL／SHM、checkpoint 或手動改表。
- 月營收／財報候選資料不等於正式 availability mapping。修復、mapping 或歷史 backfill 須依[每日資料更新指南](../../03_data/daily_data_update_guide.md)的 preview、備份和明確 apply 步驟。
- 若狀態顯示 freshness unknown、stale 或 partial，先查看資料根、實際交易日、來源診斷及同一發布週期的 receipt，再重試。不要用 `MAX(date)`、本機星期幾或目前電腦日期猜資料新鮮度。

### 每日快照的時間判讀

日曆原件下載完整與日曆已通過指定用途驗證是兩件事。本次TWSE年度／TPEx月曆已有完整候選原件與解析紀錄，新的批次保存／重開仍在隔離驗證階段；一般更新頁不會因此自動發布或切換日曆。遇到日曆unknown或期間缺件，保留來源與原因；不可把HTTP日期當官方發布時間，或把新抓版本套回較早的歷史決策。

TPEx年度股票日曆另有獨立來源版本，與TWSE年度原件形成具名年度批次，沿原保存與讀回核心及Registry表單使用；兩市場接受紀錄須同屬年度家族。日期覆蓋、完成小時與用途資格分開核對，正式Main尚未配置真接受紀錄。隔離測試的合成時鐘／接受不是官方成功批次或歷史PIT。

研究Registry已提供明示「每日批次」診斷路由，要求指定批次的manifest／成功收據雙SHA與兩市場獨立用途接受紀錄；正常Main／新程序只用合成接受紀錄限定驗證。正式Main尚未配置真接受紀錄，缺件時比較保持停用；這不代表一般更新頁、日常固定下載或正式排程已接新批次。

新快照研究使用固定成功批次保存的版本。官方發布 14:45、批次完成 15:12 時，最早可用小時是台北 16:00；只有資料基準日期而沒有官方小時時，使用成功批次完成小時並保留時間依據。資料期間不等於可用時間；未保存、品質失敗或部分批次不可當成當輪成功。已保存研究重開仍核同一批次／版本，不換成最新檔案。

首次成功保存後已通過指定用途的新快照可作日常研究；更早的歷史用途仍依實際版本證據，不能以今天抓到的旧期資料回填歷史決策。若顯示缺前期、來源／版本／hash 不符或批次隔離，保留具體原因，待取得缺件或完成該批驗證；不手改時間或補 0。完整政策見[每日快照契約](../../03_data/DAILY_SOURCE_SNAPSHOT_CONTRACT.md)，正常 UI／排程接入與真來源是否完成依[本輪 QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md)判讀。

TWSE 月營收 JSON 候選的單位未核時保留原值與具體阻塞，不自動換成新台幣或加入策略。完整保存原件的解析成功，和當輪抓取／發布成功是不同證據；下載不完整的原件仍隔離。這輪新 JSON 契約尚未接入一般更新頁或正式排程。
