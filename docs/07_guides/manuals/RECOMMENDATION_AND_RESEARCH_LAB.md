# 推薦與 Research Lab

## 個股研究工作區導覽與操作

個股研究頁標題下方分成「研究區段」與「這檔操作」兩組。用「研究內容」閱讀報告、「保存判斷」查看或保存本次研究筆記、「成果追蹤」查看已保存研究的追蹤狀態；這些是頁面導覽。要對目前這檔股票採取研究動作，使用「加入自選」、「加入比較」或「準備回測」；它們不會自動保存判斷、執行回測或建立交易。原選股來源另有「改用一般個股查詢」時，該按鈕位於同一組操作區，表示離開原來源脈絡。

寬視窗會將兩組放在同一列；窄視窗會分成上下兩列，並保留完整操作名稱。切換「研究內容／保存判斷／成果追蹤」不會重算推薦或建立新紀錄；保存動作仍須在判斷頁確認，之後可到「研究紀錄與覆盤」依股票代號或 result ID 查找歷史紀錄。

## 個股研究搜尋

在「個股研究」搜尋欄輸入股票代號或公司名稱片段，按 Enter 或「載入個股報告」。股票代號維持直接載入；名稱依目前 `companies.csv` 名錄做不區分大小寫的片段比對。唯一名稱符合時，先核對確認視窗中的代號與名稱，再選「是」載入；選「否」會留在目前報告。若名稱符合多檔，狀態列會列出候選代號／名稱，請改輸入完整代號；無符合時可改輸入代號或名稱片段。搜尋欄可輸入至 64 個字元。

名稱查找只讀目前公司名錄，不讀行情或歷史身份資料；載入報告才執行原查詢。保存快照、題材版本及帶有來源身份的研究仍由原載入路徑重驗，不因名稱相符放寬。公司名錄描述目前名稱，不能視作歷史 PIT 身份。若名錄不可讀，請使用完整股票代號。

Recommendation 若顯示「未入選」且原因為 `total_score_missing_or_nonfinite`，請查看「備註」的「啟用計分指標缺值」；它列出本次設定啟用、但最新列缺少或不是有限數值的輸入。此說明只定位缺分原因，不會補值或放行該候選；若顯示 `score_inputs_not_identified`，代表目前無法將缺分精確歸因到指標欄位，仍按缺分處理。

在後繼原始碼的「已保存推薦／策略研究」精確讀回中，canonical 與唯讀舊格式保存結果只有 1–4 筆候選時，表格會按實際列數縮短，原來源與推薦理由會較早出現在結果區；0 筆保留空表框與「原結果沒有推薦列」等原狀態，不能解讀為已產生推薦。五筆以上及新執行結果沿用五列最低高度。請仍核對原結果 ID、保存日期、來源與品質；畫面縮短不使舊建議成為今日建議，也不授歷史 PIT 或交易資格。固定舊 EXE 未包含 M155。

「已保存推薦／策略研究」在窄版仍沿頁面垂直捲動閱讀；保存來源選單、結果表與人工決定區會保留各自所需高度，不應被壓成細線或重疊。若看不到下方欄位，先沿結果區捲動；若選單或按鈕明顯裁切，記錄視窗尺寸與所處頁籤回報，避免改選另一筆保存來源。

M160 Advice 判讀：決策工作台「今日 Advice 與研究輸入」先看模式、決策／資料日、Advice 與配置列數及原警告。Advice 卡片另顯示保存列的規則分數、同日 eligible universe 的分數百分位與母體日期／大小、產業和行情原值；缺值顯示未提供，規則分數不是 AI 信心或勝率。再選 Advice 或配置列檢查原理由、逐股證據、風險和失效條件；重複的共用警告／資格限制集中於 Advice 區塊，展開仍可查原始詳情。長文在共用證據明細；表內中文僅為已知原碼的顯示，原碼可從提示核對。Advice 的產品身份不依 Professional／Guided 模式、candidate 或 `promoted` 狀態區分；策略生命週期與作者契約缺漏以限制提示顯示，資料與來源失格仍可拒絕或降級。Advice 是供使用者判斷與手動記錄，不是 broker order；缺件／未知不得當零或安全。尚未載入、無符合條件結果與讀取失敗各有獨立提示；讀取失敗會清除舊建議，原始代碼與診斷可在技術診斷展開查看。操作步驟見[決策工作台 Advice 載入狀態](../APPLICATION_MANUAL.md#決策工作台-advice-載入狀態)。此路徑限原始碼與隔離合成 QA，正式來源及 Owner UAT 未驗。

Advice 判讀卡將缺欄分兩類：可從同筆保存推薦結果核對的來源欄位，只有 exact result ID 對齊時才提供回查；進場論點、失效條件、策略持有期間與檢視頻率是作者聲明，須在新的合格回測升版時建立，既有版本不可事後補綁。只有當每日候選 result ID、snapshot、股票、決策日、資料日都與目前 read model 精確相符且資料未 stale 時，才可按「前往策略回測建立新版本」；Backtest 會唯讀顯示候選身分、策略版本及缺少欄位供核對，不載入設定、不執行回測、不升版、不自動填入，也不授 Gate 1。候選過期或身分不符時不顯示入口。來源列本身缺欄時維持未知，不能從推薦分數推定。

Workbench 的人工研究閉環另可對 exact 當日 Advice 設定下次檢視：確認 result ID、股票、決策日、資料日與來源 snapshot ID 一致且資料未 stale 後，手動指定台北時間；保存會立即讀回同一候選核對，不依策略檢視頻率自動排程。身份改變或讀回未吻合時保留未確認狀態。研究時間紀錄不代表採用 Advice、交易或 Gate 通過。

V2.2 weekly evidence collector 產出的週期包只能作為待審資料。讀 Markdown／approval packet 時核對交易日期數、觀察列數、重複股票日、OHLC 缺值與成交活動；若附官方 receipt hash，代表同日封存 bytes 已通過 SHA-256 核對，並可區分官方 `--`、本機漏掉官方價格及原因未核實。官方 `--` 仍表示該列沒有可用 OHLCV 價格，不能自行補價。`pending_human_review` 不等於已審或 Formal credit；source coverage 分母、發布／可得時間、授權或完整 universe 未提供時仍視為未知。Workbench 若指出舊收集缺可核來源或 coverage，這代表需要以目前來源重新收集；Owner 核准不能補出缺少的證據。collector 只讀正式行情 SQLite 與同日 custody 封存，sidecar 及報告不會替代具名 review 或 approved history。

每日推薦快照如無候選仍會保存同次決策時鐘，使結果能以空／降級狀態完成後處理；`passed` 只代表快照流程完成，不代表來源覆蓋或正式 Gate 合格。`why_not_payload_rows` 是未形成候選 payload 的掃描列數，可能同時包含正常策略／流動性排除與真正缺資料；請查看「排程狀態」的 verified canonical cohort 分類及各列原因，勿將全數未選列當成資料缺漏。若出現 `snapshot_cohort_partial_source_coverage`，按「缺資料」分類與缺少代號檢查來源；不得以補造列消除警告。

策略或流動性條件正常排除的股票，會保留 `skipped` 狀態與原因，資料品質記為 `observed`；只有來源缺值、計算缺分或來源錯誤才列入 `missing`／`degraded`。舊保存結果仍按原始 cohort 顯示，重新執行後才會使用新分類；不得把策略排除當作缺資料修復，也不因品質標記改變而新增候選。

## 圖表尺度與 Fast 數值判讀

個股研究的「價格／技術」若有完整開高低收與成交量，K 線下方會顯示成交量柱，柱高依目前顯示日期範圍的最大原值縮放；兩圖之間的「成交量刻度（股）：0 至 …」標出這段資料的量級。全零只標 0，缺成交量仍沿原 K 線或收盤價圖呈現，不把缺件當零。圖表加高並顯示 MA20 金色、MA60 藍色圖例與價格網格；圖例值及游標均線值只在顯示時四捨五入至小數點後兩位，不改原 Decimal。下方只有一張「近期價格與均線」表，按資料日對照收盤、MA20、MA60、漲跌與成交量；滑過圖表或表格可讀完整 OHLC、成交額、來源與原值。單日技術快照改以卡片呈現，已核驗事件標記收在可展開區。放大或平移圖表時，刻度按目前可見日期重新顯示；表格仍保留完整來源日期範圍。

回測 Fast Canvas 圖表可用方向鍵、Home／End 或游標查看資料點；權益 hover 顯示「策略淨值」和原數值，不假定美元，回撤 hover 顯示百分比。可按「顯示數值」閱讀文字替代，並用原保存結果與交易表核對。後繼 M137 將文件載入與畫布繪製分開：本次頁面正尺寸 JS 繪圖完成才顯「畫布繪製完成」；明確 JS 錯誤顯「繪製失敗」，逾時只顯「無法確認」，不冒稱失敗原因。頁面失敗或呈現程序停止時可先讀文字數值，再按「重試圖表載入」使用目前最新圖資料。此確認不驗 GPU 合成、實體顯示或金融值；正式結果仍須用保存來源與交易表核對。這些後繼原始碼尚未包含於固定舊 EXE；隔離合成畫面與程式化鍵盤事件不等於正式來源、正式 GPU、實體操作或 Owner 驗收。

M139 僅收掉 Backtest 圖表頁兩層外圍空白：在已驗的 1280×760 Windows 視窗中，Fast 權益與回撤畫布首屏完整可見，來源 run、歷史載入、狀態與「顯示數值」仍可讀。展開文字數值或研究脈絡後，頁面可按需要捲動；其他真 DPI、正式 GPU／固定 EXE 仍須分別驗。

## 備援權益圖買賣點提示

在回測「圖表」頁，先確認「選擇回測結果」與旁邊的原 run ID，再切換權益、回撤、交易報酬或持有天數。頁面預設把重複的研究脈絡與補充查找收起，使較矮視窗也能先看到完整圖；需要查策略版本、研究歷史或 Paper 快照時按「顯示研究脈絡與查找」，離開圖表頁後原勾選狀態仍在。舊結果載入控制及內容捲動仍保留。這只是 Backtest 圖表頁的版面安排，Portfolio 圖尺寸和保存結果數值不變。

在回測或 Portfolio 的權益曲線使用 Matplotlib 備援圖時，滑過買點或賣點可讀原交易日期、價格、股數；賣點另顯原損益、報酬與持有日數（如來源有提供）。提示框使用深色圖表的文字、底色和邊框，交易內容及正負色義不因外觀改變。滑離標記後提示會清除；若 `mplcursors` 不可用，仍以基本提示顯示相同欄位。同點多筆重疊時，基本提示每側最多列兩筆並標示省略數，完整資訊請沿原圖與交易明細表核對。此後繼原始碼未包含於固定舊 EXE；隔離合成正常 Main 的程式化 Qt 滑鼠事件不代表實體滑鼠、正式來源或 Owner 驗收。

後繼 M130 讓四種 Matplotlib 備援圖及買賣點提示採系統可用的繁中字型；負號另有拉丁字型後備。系統沒有可解析候選時維持原字型，仍可能缺中文字形；此時請以圖表旁原保存結果、文字與表格核對，勿從方框猜欄位。此變更未改報酬、價格或回測判定，也未包含於固定舊 EXE。

後繼原始碼的「證據覆盤 → 資料缺口」在警告總數旁提供預設收合的「警示文字頻次」。展開可看本次篩選中最多五種原警示文字與出現次數，其他文字合併計數；分母是文字出現總次數，一筆持倉可有多則警示。來源診斷或統計與逐列不符時顯未知，不能當作沒有警示。這是資料缺口摘要，不代表研究結果、匹配或來源資格已通過。

「策略實驗室 → 回測分析 → 證據覆盤」的「前瞻績效證據」若列出 `corporate_action_source_not_ingested` 或 `trading_restriction_source_not_ingested`，警告欄會同時顯示「企業行動資料來源尚未納入」或「交易限制資料來源尚未納入」、原碼與筆數。未知警告仍顯原文。這些警告代表來源尚未納入，不代表事件不存在；不得用行情價格、其他股票或相鄰日期代替企業行動／交易限制證據。切換群組列後，在右側明細核對同列的樣本、品質和警告分布；來源缺件不會因 outcome 顯示 `ready` 而解除。

## 個股營收與籌碼圖卡

從原選股、題材、自選或保存研究進入個股，摘要先呈現營收、法人、信用、集保四個面向的原值與資料日；按「查看章節」深入。也可於「研究章節」選「基本面與營收」或「籌碼與產業事件」。圖卡使用這份報告已提供的原值，不另外查最新資料；保存副本仍是當時版本。籌碼頁固定列法人、信用、集保、分點摘要，再由「展開詳細圖表與原表」查全部已載入欄位，不以法人前四欄遮住其他面向。

- 營收依指標、市場、來源版本、已知單位與已核期間基礎分組；已核實的新台幣仟元 MOPS 靜態快照及 F22 明細修訂會換算為 TWD 顯示，其他單位未核來源不顯示推測金額。資料須等到其來源版本的可得日才可見，修訂版不會回溯改寫舊 snapshot 或公告時點。多月份用時間柱圖，缺月保留間隔、不補值，缺值不當零。財報當期／前期用配對柱圖，只畫原比較值，不重新算同比。只有一筆則顯示值卡，不假裝趨勢。
- 法人淨額可在同日同來源同單位比較；買進、賣出、信用餘額與其他指標分開。只有一筆時只顯示原值，不用滿長橫條暗示量級或趨勢。
- 集保級距顯示原比例基點，100基點為1%；調整與合計不混入分布。單日快照不能判斷大戶增加或減少。
- 分點按同日、來源與交易類型列原順序前12筆，標明顯示筆數／原分母；下方仍可查完整原表。不累計、不生成主力連買訊號。
- 價格、漲跌及淨買賣方向使用紅漲／正、綠跌／負，並保留正負號；零值中性。個股日 K 線與成交量柱按同日開收盤原值配色，平盤中性；缺完整開高低收時退回收盤線圖。營收、餘額、成交額與一般原值用中性色，不把正值判為利多。正常／錯誤的狀態色另有語意，不代表漲跌。不同圖卡不可比較條長。日期、可得時間及品質需一起判讀；未知單位／期間或歧義資料留在原表，不為畫圖補成已知。

窄窗會上下排列，圖卡不另設內層垂直捲動；沿頁面的主捲動閱讀。只有在可見月營收柱圖逐列對應所有月營收原表列時，原表才預設收合；按「展開逐筆月營收原值與來源明細」可查精確原值、期間與可得時間，資料日、品質及來源可由欄位提示核對。來源／期間未核、圖卡無法顯示或圖表未涵蓋全部原表列時，原表會直接顯示。展開鈕可用鍵盤操作；其他圖卡失敗時仍保留原表。缺資料須由原資料流程處理。這項 UI 不更新正式資料、不改金融資格、不執行 Daily Operations Recovery 或排程。

報告載入後搜尋列會收合；按「切換股票」可重新輸入，重新載入與上一／下一仍在上方。股票身份旁以大字顯示本報告原收盤價，原漲跌與行情日緊接在下一行；漲跌只按原同日 `change` 值顯台股紅漲、綠跌，零／缺值中性，行情日保持中性色。滑過行情區可核來源、可得時間與品質。缺報價仍顯示未知，沒有原百分比就不另算。「來源與研究日期明細」列完整上下文。五問先保留短結論、證據、變化、風險與不足，按「展開五問證據與限制」讀全文；窄視窗會讓保存推薦摘要依文字換行增高，不裁掉換行內容。報告讀回只表示讀取成功，各面向仍可能缺件；重載失敗時核對是否保留上次同股資料，不能當成本次成功或最新行情。

摘要中的「價格走勢｜原研究版本」只在同一份研究的價格列已通過股票、日期與來源脈絡核對後顯示圖表。價格缺件、來源／日期核對失敗或圖表無法呈現時，圖表卡會收起，五問摘要下方改顯一條價格與報酬狀態，並指出可查看「價格與技術」章節；不會用其他版本或最新行情補圖。尚未選取／載入股票時也以同一位置提示下一步，不預留空圖卡。

在 1280×760 主視窗，行情日會完整顯示；若來源只給正數價差卻沒有可信漲跌方向，頁首顯「未知」且維持中性色。資料日只標示這筆行情所屬日期，不能取代來源可得時間。合成 SQLite 的載入測試已核這些呈現，正式價格來源仍要另行驗證。

關閉再以相同目錄與雙SHA啟動，讀回同一原件版本；這是來源版本保存，不是新增財報收藏或前期比較按鈕。來源檔缺件、SHA漂移、pending／failure或尚未到台北成功批次可用小時，該來源不可用，其他報告區塊仍可讀。2330以外的公司和前期成長率維持原缺件，不從PDF補入數值；此來源不供歷史PIT、選股評分、策略、ML或交易。實際Main／EXE驗收與已知問題依[Increment117 QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md#increment117-operating-summary)，不能由設定存在推定通過。

「研究 Registry」另有「配置研究紀錄（非回測績效）」：情境須先在持倉管理保存並明確登錄；輸入帳種與完整 portfolio_id、載入後明選一筆，按「開啟所選紀錄」回到原配置研究封存。這類紀錄不加入回測多選比較或 promotion，也不補本金、績效或 equity/trades；登錄時間不是原資料可得時間。步驟及原件缺失／版本錯誤排錯見[登錄研究指南](WATCHLIST_AND_PORTFOLIO.md#登錄研究紀錄與跨頁重開)。此為後續開發分支功能，固定 `4b530a7e` 試用包不含。

## 推薦分析

### 找回已保存研究決定

決策工作台的「已納入研究／略過」會記錄在 Journal，不建立交易或 fill，也不會永久留在今日 Advice 清單。狀態中的「另加註記 0 筆」只計附加的文字筆記，不含已保存的研究決定；研究動作歷史會另列決定與修訂。要回找舊決定，開啟「研究紀錄與覆盤」，在「查找已保存研究紀錄」中把來源選成「研究決定」，輸入保存時的完整 `result_id`；如果只有股票代碼，也可輸入代碼搜尋。從 Advice 按「研究紀錄與覆盤｜查找這筆」時，頁面會自動切到「研究決定」來源並以該 `result_id` 查找，不受你先前選取的其他來源篩選影響。列表最多顯示最新 500 筆；搜尋區會明示研究決定不依賴今日 Advice 清單，並把目前清單符合數、完整 Journal 搜尋結果與零符合分開提示。顯示上限時，完整 result ID 搜尋會查完整 Journal 歷史。選取左側「研究紀錄清單」中的紀錄後，右側「所選紀錄與延伸操作」顯示原文及可用操作。重新讀取只重讀 Journal，不會重建 Advice 或改寫原決定。若仍找不到，先核對 result ID 與來源狀態；列表上限或來源讀取警告不能解讀成該紀錄已不存在。

後繼Source從「產業與題材」進入的一般個股報告，脈絡列標「題材版本資料日」，價格區另標行情日期；原題材來源內不可直接換代碼，先返回選成員。題材判斷的保存、追加修訂及重啟回訪在[題材研究步驟](DATA_AND_MARKET_RESEARCH.md#產業與題材後繼source)，不改既有推薦或策略保存規則。

### 建立一輪候選

1. 查看頁面上的市場狀態、資料日、來源與 warnings。
2. 新手模式可選一個內建 Profile，或套用系統提示的 Profile；先讀對應的權重與篩選說明。自訂 Profile 會標示未經回測驗證；策略版本 Profile 只表示它符合該版本既有選用條件，不代表實盤驗證。
3. 進階模式可調整技術指標、圖形模式、最小漲幅、最小成交量比率、產業、評分門檻，以及可選的月營收 YoY／PE 條件。啟用的指標必須有足夠歷史資料和合法參數，缺值不會補成零分。
4. 選擇固定門檻或百分位排名，確認 eligible universe、最小母體數與 top-N，再按「執行推薦分析」。

設定解讀：

- `pattern`、`technical`、`volume` 權重以整數基點表示，總和必須為 10,000 bp。buy／sell score 是結果判讀門檻；改門檻不會改變各指標如何貢獻分數。
- 啟用月營收或 PE 篩選時，既有歷史版本仍按 `available_date <= decision_date` 判定；明示pinned每日快照另核台北小時可用性與含時區截止時間，發布時間與成功批次時間向上取整，不提前使用。基本面缺件會留在screening matrix，不能用目前最新資料填入歷史決策；此政策不表示正常UI每日批次入口已完成，詳[資料與市場研究](DATA_AND_MARKET_RESEARCH.md)。
- 固定門檻使用既有絕對門檻；百分位依當日 eligible universe 排名，會受最小母體數與前置條件影響。quantile 維持 opt-in，不能只因排名靠前便宣稱優於 fixed。
- 「取消分析」是合作式取消。等待安全收尾期間不會套用不完整結果，上一筆完整結果會保留。

### 舊回測保存格式與精度

116固定候選中，正常單股／批次執行仍用原保存入口；新曲線與交易的數值附註不再因Decimal序列化失敗而轉存CSV。有限Decimal欄保持原值，附註以精確文字保存，原日期與交易不重算。來源Main四筆原結果已核讀一致；固定116 EXE另核高精度新保存與另一程序讀回，原四筆沿歷史唯讀回訪，未重算策略。115及更早包保留原限制；見[116交付QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md#increment116-fixed-trial-delivery)。

舊CSV及資料庫摘要不會自動遷移；歷史CSV可能已在讀取時失去精度，不能靠顯示更多小數位或轉回Decimal恢復。若仍遇到「改用CSV」或原件讀取警告，記下run ID、檔案路徑及原錯誤交owner檢查，不手改副檔名、不覆寫舊run，也不把缺附註補成已核來源。引擎既有float DTO與SQLite REAL摘要的資格限制仍保留；本修補只防止保存新增流失，不授來源、歷史PIT、績效或晉升資格。

### 閱讀結果與保存

後繼原始碼的標準推薦結果表先顯示候選摘要；按表格標題旁「顯示延伸欄位」可核對完整校準、模型與來源欄，再按「收合延伸欄位」返回摘要。切換只改可見欄位，保留同一選中股票和原保存資料。未入選篩選紀錄及舊格式保存結果仍顯示完整原欄，應核對「未入選」、原因、觀測／要求值、決策日或舊保存欄，不把它們當本次可用推薦。固定試用 EXE 尚未包含此版面修改。

推薦結果上方的「本次資料日期與來源」展開全體分析上下文：決策日、行情資料日、Profile、保存來源與 result ID；表格選取列後，下方「推薦理由詳情」的「查看此股完整來源與核驗資料」則查看該股票的來源快照、契約與資格限制。上方摘要只列本次行情資料日及候選／未入選筆數；狀態列說明分析狀態與選列後可讀的理由、風險和逐股來源，兩處不重複列判讀步驟。摘要與切換入口在結果欄寬至少 560 px 時並排，窄欄才上下排列。保存與載入已保存結果仍在「讀取已保存結果」控制列。

由已核驗composition明示使用每日cohort時，上市／上櫃各自綁批次與原件；所有必要市場都成功後，以較晚小時判定整組可用。同次推薦來源追溯會帶cohort hash/pin及各股實際讀取狀態；missing／unknown仍是缺件，不是通過。正常Main成對配置及新程序的合成輸入重開已有限定QA，但完整推薦執行／結果保存／真人與EXE旅程仍待；不能以打開月營收篩選checkbox推定已選每日cohort，原歷史模式仍依其版本證據。

Registry年度binding與上述重開／比較／返回操作已有固定`675bea26`來源／候選EXE同版的合成Main／新程序證據；其他交付仍各自依版本與收據核對。這不授真雙市場來源、PIT、完整績效或Native真人資格，詳[Increment31 QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md#increment31固定來源候選exe與registry同版旅程)。

### 選擇已接受範圍的固定月營收快照

1. 先保留既有一次性來源／用途接受紀錄與完整批次pin。由受信服務產生binding配置原件；來源接受、批次品質與版本選擇分開判定，切換下一個成功日批次不代表重新人工接受來源。
2. 在既有Baldr `config.json` 加入 `MONTHLY_REVENUE_COHORT_BINDING_PATH`（外部binding檔案的完整絕對路徑）及 `MONTHLY_REVENUE_COHORT_BINDING_SHA256`（該binding原件的64位小寫SHA-256）。兩項須一起提供；亦可由同名環境變數覆蓋。hash應由受信配置提供，不用snapshot自述hash冒充來源接受。
3. 正常啟動或新程序重開時，Main核配置、所有必要市場及固定版本後，交給同一推薦preparer/provider。部分配置、hash不符、缺市場、symlink／reparse或包內來源會拒絕；保留原檔與錯誤，核對所選版本及接受範圍，不手改hash掩蓋缺件。
4. 啟用目前月營收條件後仍須核同次決策截止時間、共同可用小時、實際資料狀態及warnings。既有無此配置的使用者維持原來源路由；這不是自動選latest、補歷史或啟用正式排程。完整來源證據與正式日常更新接線仍按[本輪QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md)判讀。

先核對 result ID、決策日、資料日、Profile、母體、quality 與 warnings，再閱讀 Why、Why Not、分數拆解及 screening matrix。`missing`、`degraded`、`skipped`、`failed` 是不同原因；有效空結果不等於來源缺失。Regime confidence、reliability 或 rule score 不是未來勝率。

按「保存結果」可把目前完成的一輪存入 canonical research source；畫面會以同一結果 ID 做讀回確認。保存失敗或 readback 未通過時不要手改 hash、複製 artifact 或把最新檔案當成同一結果。只有已保存且 verified readback 的列才能加入觀察清單或沿來源連到持倉。

### 舊格式已保存推薦的唯讀回訪（試用版90）

搬遷副本須有獨立原件證據，包含原路徑、result ID、原始 SHA 及 DB row 核對；當前檔案 hash 或16/28/44清冊分層不能自授 custody。具名原 Git 文件可作有限證據錨點，其餘缺證項仍拒絕一般讀回；顯式稽核 envelope 必須保留 research_only 與 custody_verified，不能轉普通 DTO 丟掉限制。完整歷史清單未通過時不回傳部分結果冒充全部，亦不改寫原DB或搬遷收據。詳[Track B獨立驗收](../../06_qa/BALDR_TRACK_B_DATA_OPERATIONS_20261022.md)。

在「推薦分析」上方的「讀取已保存結果」按「讀取可用來源」，明選標示「舊格式推薦／唯讀」的原 result ID，再按「讀取」。這只沿原 reader 精確讀回，不重跑推薦。清單會區分「獨立雜湊已核」與「僅當次原件雜湊」；後者只有讀取時所見原件的 SHA-256，沒有獨立可信來源值。若選取後原件或身份變動，畫面保留原結果並要求重新讀取來源，不改選最新檔案。

載入保存結果區分兩列：第一列選擇來源並讀取可用來源；第二列執行每日推薦、取消讀取、輸入或讀取指定結果 ID，以及前往 Workbench。取消讀取只在來源清單或單筆結果載入時顯示。窄視窗（結果區寬度小於 560 px）會將兩列按鈕改為垂直排列；有結果時沿結果頁外層捲動查看下方結果表與判讀區。若下方內容看似消失，先確認結果頁外側捲軸位置；收合中的來源詳情不應攔截結果頁捲動。

結果表格顯示原保存代號、名稱、收盤價、分數和理由。選一檔按「查看個股研究」，再切到個股頁的「決策→結果」；要返回，在「個股研究報告」頁籤按「返回來源清單」，原 result ID 與選取列保留。原保存決策日只是檔內聲明；沒有可核對的行情資料日就保持未知。原值、來源 `ready` 或已連結的結果均不代表歷史 PIT、官方資料用途、核准績效或實際交易。舊格式頁面不提供重新保存、加入觀察清單、持倉交易、個人採用或推薦回放資格；需要這些操作須另有 canonical 保存與相應來源驗證。

## Research Lab／策略回測

後繼 M111 在「最佳化／驗證」原 Top-N 文字摘要與結果表之間，顯示最多八個參數的橫向集中度條。條長是**目前保留、有效 objective 排序最多前五名中，該參數有值樣本的眾數占比**；旁邊的 bp 是原精確值，括號 `有值數／Top-5 實際筆數` 揭露覆蓋，缺值顯未知而不畫條。文字摘要保留其他參數與原範圍。新掃描、樣本不足或空結果會清舊圖；空結果亦清舊文字與表。這不是完整參數面、統計穩健性、OOS、報酬或策略資格，仍須另做 Walk-forward／OOS。

後繼 M112 的「綜合選股 → 母體漏斗明細」可展開最多六個條件的五態分布；圖例分別為符合、不符合、未知、未評估、不適用，原精確計數仍在下方。各條依自己的分母，條件可能重疊，**不能把長條依序相減或當成跨條件排名**。零分母保留原 0 但不畫比例；缺件、無效或總數不一致時不畫條並保留原文。來源操作失敗／取消或尚在處理時舊圖清除；查詢身份與資料日仍以頁面原標示為準。圖條只表示目前來源結果已提供的分類，不新增選股或來源資格。

參數掃描完成後，在「最佳化／驗證」先核目標指標狀態與表格各績效欄；已簽單股契約的觀測零保留為 0，不可用值留空，原回測未完成、目標不可用或契約不符的組合不參與排名。舊無契約報告只維持相容排序，畫面標示未驗證，Top-N 有效樣本數不包含其分數。按欄排序後再選列套用，畫面按所選列的排名對回原參數；仍須另做 OOS／Walk-forward，不把掃描排名當策略資格。若沒有可排名結果，先檢查資料期間與來源契約，不以缺值補零。

Paper保存快照區需先明示外部 `PAPER_CONTRACT_ARTIFACTS_ROOT` 絕對路徑，並使用PERSONAL store；未設定、路徑無效或啟動時因權限／目錄變動而無法安全解析時，Paper 查找顯示停用原因，其他 Research Lab 功能仍可用。此時先核對路徑與讀取權限，再重新啟動；不要改用另一個未核來源補讀。展開後輸入策略、版本、帳戶命名空間及含時區截止時間，按查找列出最多200筆候選；截斷提示代表清單未列完，不自動挑選最新項目。選取所需operation／snapshot後讀回對應卡片，來源版本沿用正常策略版本選取，操作不建立或更新任何帳戶資料。

清單候選本身未驗證。快照exact讀回成功也不代表底層來源可得性、完整期間曲線或績效資格已合格；未提供指標保持空值並列明原因，不能把零成交當零報酬。關閉工作區會取消未完成讀取並拒收過期回覆；需要重新查找時重新輸入原保存身分。設定與完整步驟見[主操作手冊](../APPLICATION_MANUAL.md)，驗證界線見[本輪QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md)。

| 模式 | 用途 | 輸入範圍 |
|---|---|---|
| 單股回測 | 研究一檔股票與策略的歷史交易 | 股票代號或個股研究來源 |
| 批次股票回測 | 比較同一策略在多檔候選上的表現 | 候選池／股票清單 |

執行前設定：策略來源、股票母體、開始／結束日期、初始資金、手續費、滑價、停損／停利、部位大小、最大持倉數與市場限制。輸入成本與金額按畫面欄位的單位填寫，保存後以 run manifest 為準。

後續開發分支的單股／逐檔回測、規則卡與 Walk-forward 使用當次選定策略的登記版本；參數掃描在讀行情前固定該輪版本，所有組合沿同一版本。基準策略目前為 `1.0`，暴衝與穩健策略為 `1.0.0`。版本缺漏、空白或互相衝突會顯示「策略版本不可用」，應重新選取有效策略，不能手改 run 或把版本補為 `1.0`。這項修正尚未納入固定 `9fa4518c` 試用包。

- 執行價格建議 `next_open`：訊號日收盤後，最早於下一可交易 session 的有效開盤成交；缺開盤、零量或停牌不回退使用收盤價。`close` 是同根 K 收盤成交假設，需在結果中明確揭露。

- 交易次數為完成進出場配對；已買入但期末未平倉時可仍為0，摘要顯示「尚無已完成交易」。即時結果分列原成交筆數與期末持股，缺欄位為「未提供」；歷史頁不從零配對補造成交數。期末權益含未平倉估值，不是已實現損益或正式績效。缺分數／門檻不推論未成交原因；第一版主要驗收為正常固定門檻研究。

- Optimization 與 Walk-forward 是互斥研究模式。最佳化結果是 in-sample 候選；更換參數前先看 OOS／Walk-forward、交易數、回撤和不同期間穩定性。

### 執行、取消與結果

畫面下方唯一的主要執行按鈕會依模式顯示本輪工作內容。開始後，取消按鈕會停止提交新工作並等待已啟動任務安全收尾；不要把仍在收尾的畫面當作已取消或已完整完成。

若執行器直接回報錯誤，關閉錯誤提示後仍可在「實驗摘要」讀到本次失敗原因；該次沒有可判讀結果，保存、匯出與升級入口會停用。先依錯誤原因處理來源或設定，再重新執行，不要把前一輪結果當成本次結果。

結果檢查順序：

1. 核對 run ID／狀態、日期區間、股票母體、策略版本、成本、成交假設和 benchmark。
2. 結果摘要卡先看原總報酬、原最大回撤、完成進出場配對數和成本假設；下方文字保留 SOP、年化報酬、Sharpe、勝率、期望值與警告，不再重複卡面數字。當次執行觀測另列實際成交筆數、交易明細列數與期末持股；缺件維持「未提供」。接著再讀 coverage、warnings、equity／drawdown 圖、交易明細與逐股結果。
3. 進入「研究 Registry」時，清單首次載入與按「重新整理」會在背景讀取。狀態列顯示載入／更新狀態、已載入總數與目前符合篩選的筆數；類型、策略及標籤欄只篩選目前已載入的清單，要讀取最新資料請按「重新整理」。窄視窗中篩選欄會分兩列排列，清單的翻頁與比較動作也分列顯示，無須橫向拖動才能看到欄位或按鈕。刷新期間保留舊清單；若更新失敗，狀態會標明失敗並保留原清單，可將游標移到狀態列查看錯誤，再重試。比較 Registry run 前先看畫面標示的「可直接比較／需謹慎比較／不可直接比較」及原因；未知欄位保持未知。
4. 「保存結果」只接受本輪成功完成且尚未被新一輪取代的結果。一般視窗的設定欄在結果出現後可能隱藏；此時在「實驗摘要」旁按「保存這次回測」，輸入名稱／備註，成功後記下畫面上的 Registry run ID。到「找已保存結果」明選同一 run 重開；歷史結果是唯讀，不能再次保存。若保存成功但歷史清單刷新失敗，保留 run ID 後重新查找，不要為刷新錯誤重複保存。
5. 「升級為策略版本」須符合目前所選來源的 Registry、驗證及 lifecycle gate。新保存的單股回測已存在 Research Run Registry；升級檢查、版本建立及回鏈使用同一 Registry run。成功前會讀回 StrategyVersion JSON 與 Registry，核對來源 run、策略、參數、Advice 契約及 `promoted_version_id`；失配會明示失敗並留下待 reconciliation 狀態，不顯示升級成功。單次高報酬、最佳化排名或一份 replay 都不足以證明策略實盤有效；升級也不等於下單權限或正式 Gate 接受。
6. 策略作者可在新版本建立時填寫版本化建議契約：進場論點、失效條件（每行一項）、策略持有期間與檢視頻率；四欄只在作者選擇保存契約時需填妥，缺少它們不阻擋 Advice；也可明確選擇「略過（不保存作者契約）」，此時建立的版本不帶 Advice 契約，之後不能事後補綁；但沒有作者契約仍可依保存策略與來源證據取得 Advice。取消契約輸入會取消本次升版。成功提示會說明契約 hash 是否已讀回核對；建立版本本身不代表策略效能或資料來源已通過驗證；Advice 仍會揭露其證據成熟度。契約綁定新策略版本並帶內容雜湊，之後只有選取該精確策略版本 Profile 執行的 canonical 推薦會封存並顯示它；舊推薦、舊策略版本、其他 Profile 或未通過保存完整性核驗的結果都不會補入契約。論點、期間或失效條件不會由績效、校準期間或推薦理由推定。

研究結果保存其參數、資料指紋、成本／成交假設與結果摘要；來源追加新資料不會重算原 run。保存、讀回或比較出現完整性錯誤時，先保留錯誤與 run ID，再依 owner 維運程序查詢，不手動改 Registry 或 artifact。

結果頁明列尚未保存、已保存的 run ID 或 Registry 不可用原因；保存失敗時保留當次畫面供核錯重試。重開歷史結果則停用重新保存，須執行新實驗才可保存新結果。策略版本修正只影響新請求，舊 run 的原版本保持不變，不自動升級或補認證。版本一致也不表示來源、歷史 PIT、績效或升級資格已通過。

這些來源頁的查詢和讀回不會自動跑 producer。頁面上如另有「產製技術與官方來源研究」，那是明示的研究產生工作，與更新 catalog 或讀取已發布快照不同。若外部來源被標為唯讀，產製／續跑可能停用；不要改用另一個來源 root 解鎖。若 available time 未知、scope 不完整或母體身份未核，保留 unknown；研究頁的排名、比較與收藏都不因此成為 PIT、推薦 Advice 或正式訊號。詳細來源 pin、跨頁返回與 store 路由契約見[目前應用架構](../../01_architecture/current/application_and_workspaces.md)與[目前資料儲存架構](../../01_architecture/current/data_storage_runtime.md)。

## 個人 H20 保存研究

「推薦分析 → 個人模型選股研究（H20毛報酬）」讀取已保存的完整 H20 母體。開啟分頁時會核驗原保存來源；也可按「讀取每日已保存模型名單」重讀。若頁面仍在讀取，等狀態返回；要取消時按「取消名單讀取」並等安全收尾。取消或核驗失敗不會把部分名單當成有效，也不會用另一個 cycle 替代；完整錯誤與來源身份可在頁面選取、複製。

名單只列原 manifest 成員，欄位包含股票、H20 毛報酬（bp）、狀態、決策日、來源日、特徵截至日與原因。排序只改同一原 manifest 的列順序，不是全市場排名。選「可核原預測」列後按「研究選取股票」或雙擊，進入沿原 H20 來源的個股研究；按「收藏原保存 H20 研究」則保存該版本身份，之後從觀察清單精確重開。未知列會停用研究／收藏操作；不要以另一檔股票、另一個日期或重算值代替。

H20 是未扣成本的 20 交易日毛報酬估計，不是勝率或機率，也不代表模型有效、自然結果已成熟或值得買進。個股報告中的 H20、H5 成本後超額與一般最新行情是不同投影；若原保存 H20 沒有綁定同版本價格／技術圖表，不會由一般報告補造。若畫面提示沒有安全副本目錄，讀取尚未開始；依首次安裝／移機流程由 owner 核對 H20 來源與安全副本設定，不要任意改根目錄或複製模型資料。

目前 UI 與來源 reader 可在 `ui_qt/main.py`、`ui_qt/widgets/personal_h20_research_widget.py`、`app_module/recommendation/personal_h20_verified_cohort_view.py` 及 `scripts/scheduled/personal_h20_daily_hook.py` 查閱。存在讀取入口不等於個人模型通過自然成熟、品質或產品 Gate；整體現況看[目前狀態快照](../../00_core/PROJECT_SNAPSHOT.md)，具名 QA 收據仍只說明其記錄的版本與範圍。

### Immutable ML artifact 保留界線

一般使用者不應清理、搬移或改寫 release、ML manifest、latest pointer 或其 lineage。現行 `scripts/inspect_ml_storage_retention.py` 只提供唯讀 metadata inventory，並沒有 destructive retention runbook；需由 owner 依[資料儲存架構的保留與核准邊界](../../01_architecture/current/data_storage_runtime.md#immutable-ml-retention-的目前檢視與核准邊界)處理。歷史 Supplements 內的 retention 命令與 QA 不是目前可執行步驟或授權。

## 常見問題

### 獲利因子的可用性與舊結果

最新PF試用修補版 `4b530a7e` 已由 `output/trial/Baldr-V1-PF/Launch-Baldr.cmd` 提供；原生EXE的回測／保存對話框／歷史／返回／新程序已限定重驗。下述9fa限制仍適用舊包，原件保留；新包只回移PF修正，不含新歷史七指標卡。新包的保存輸出與私人狀態獨立，沒有自動搬移舊試用結果。

後續開發分支已修正原「無虧損時把獲利金額當獲利因子」的錯誤。PF是已完成配對的總淨獲利除以總淨虧損絕對值，沒有金額單位；費用與滑價沿原配對淨損益。混合盈虧顯示有限比率，只有虧損時有效值為0。零配對、全部獲利且無虧損、總獲利／虧損皆零分別顯示具體「未提供」原因，不補0或無限大。

單股摘要、批次與最佳化匯出保留狀態／語意版本，舊runs表缺版本不作有效比率，舊比較及升級摘要PF不可用。原保存列不回填、不重算；新未定義值保存NULL，未遷移schema。歷史七指標卡未保存PF，不反推。

**固定9fa試用EXE尚未包含修正**：其附加PF在無虧損或零配對時不可當有效比率。這項金融錯誤列為V1-04窄版修補阻擋項；source測試不等於固定EXE已修好，四條凍結流程不擴張。

### 新單股保存結果的歷史指標（後續開發分支）

當次單股回測的完整文字摘要也沿同一版本化指標契約判讀：總報酬、年化、夏普、最大回撤、勝率及期望值若標不可用，顯示「未提供」；契約無效時不退回原始零值。已完成配對數有自己的觀測狀態，權益曲線缺失但確有零配對時仍顯示 0。舊未宣告契約的結果保留原摘要格式；這只是展示投影，不重算績效或補歷史資格。固定試用 EXE 尚未包含此修正。

### 批次逐檔保存與歷史（Increment110 開發來源）

批次回測執行後，在研究 Registry 已配置的入口，排行榜的 `RunID` 只在舊格式與 Registry 均完成保存後顯示；未配置 Registry 的舊入口仍只代表本地舊格式。完成提示分開列回測檔數與已保存檔數；某檔保存未完成時，排行榜「失敗原因」會顯示具名錯誤，該列 `RunID` 留空，不能當成可重開的結果。計算完成與保存成功是兩種狀態，不能用整體成功檔數推算保存筆數；保留錯誤，不修改原 run 或自行補寫 Registry。

批次排行榜的 CAGR、Sharpe、最大回撤及勝率遵守各股原版本化指標有效性：不可用的數值不以底層預設零冒充樣本。CAGR 與最大回撤中位數在 `n=0` 時顯「未知」，有效樣本的真零仍為 `0.00%`。舊 run 若沒有該契約，沿原舊版值呈現；不能由此推定其歷史來源已核可。

在決策品質分頁指定覆盤類型與日期後，流程分數、待處理等項目計數與明細表會對齊所選覆盤。明填 Portfolio ID 時，只納入保存時具相同原身份的覆盤；舊紀錄沒有身份就不猜成指定 Portfolio。若沒有符合的覆盤，表格保持空白，不借其他範圍的項目填入。這是唯讀篩選，不會改保存的覆盤或原分數。

項目類型、嚴重度與狀態的已知原碼在表格顯中文，原碼可從儲存格提示與選列詳情核對；未知碼維持原文，缺值顯「未知」。來源類型與篩選契約不作推測性翻譯。

「最低分數」只接受空白或 0–10000 整數；非法值重新整理時會顯示欄位錯誤並清除舊卡片與項目，不讀取新來源。更正後再重新整理。股票代號只篩項目列；分數卡仍是所選覆盤範圍的最新整體分數。最低分數以篩選後最新覆盤的整體決策品質分數作門檻，未達時只清空項目列，分數卡保留原值；它不是逐項門檻，也不重算分數。

1. 兩次獨立推薦回放完成後，各按「保存推薦回放」、填名稱並確認；記下原 Registry run ID。歷史讀回結果不可重存，可沿原 run 重開。
