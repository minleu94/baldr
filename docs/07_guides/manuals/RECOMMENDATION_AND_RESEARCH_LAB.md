# 推薦與 Research Lab

本手冊說明如何建立研究候選、保存一輪推薦、做歷史回放與解讀回測。每次先確認股票母體、決策日、行情資料日、成本／成交假設和來源品質。歷史研究只使用決策當時可取得的資料；可讀的模型投影、回放或一次高報酬都不是自然證據或實盤績效。

從後續開發分支「配置研究封存」進入個股時，持倉分頁顯示該已保存情境的原帳戶及 targets，不查今日同股手動持倉。比較預覽須先另存；原 mark 時間缺件不以帳戶時間替代。操作、錯誤及返回見[配置研究指南](WATCHLIST_AND_PORTFOLIO.md#配置研究封存與另存假設)，完整初始來源與 P06 仍待，固定試用包不含此後續增量。

## 推薦分析

### 建立一輪候選

1. 查看頁面上的市場狀態、資料日、來源與 warnings。
2. 新手模式可選一個內建 Profile，或套用系統提示的 Profile；先讀對應的權重與篩選說明。自訂 Profile 會標示未經回測驗證；策略版本 Profile 只表示它符合該版本既有選用條件，不代表實盤驗證。
3. 進階模式可調整技術指標、圖形模式、最小漲幅、最小成交量比率、產業、評分門檻，以及可選的月營收 YoY／PE 條件。啟用的指標必須有足夠歷史資料和合法參數，缺值不會補成零分。
4. 選擇固定門檻或百分位排名，確認 eligible universe、最小母體數與 top-N，再按「執行推薦分析」。

設定解讀：

- `pattern`、`technical`、`volume` 權重以整數基點表示，總和必須為 10,000 bp。buy／sell score 是結果判讀門檻；改門檻不會改變各指標如何貢獻分數。
- 啟用月營收或 PE 篩選時，既有歷史版本仍按 `available_date <= decision_date` 判定；明示pinned每日快照另核台北小時可用性與含時區截止時間，發布時間與成功批次時間向上取整，不提前使用。基本面缺件會留在screening matrix，不能用目前最新資料填入歷史決策；此政策不表示正常UI每日批次入口已完成，詳[資料與市場研究](DATA_AND_MARKET_RESEARCH.md)。
- 固定門檻使用既有絕對門檻；百分位依當日 eligible universe 排名，會受最小母體數與前置條件影響。quantile 維持 opt-in，不能只因排名靠前便宣稱優於 fixed。
- 「取消分析」是合作式取消。等待安全收尾期間不會套用不完整結果，上一筆完整結果會保留。

### 閱讀結果與保存

由已核驗composition明示使用每日cohort時，上市／上櫃各自綁批次與原件；所有必要市場都成功後，以較晚小時判定整組可用。同次推薦來源追溯會帶cohort hash/pin及各股實際讀取狀態；missing／unknown仍是缺件，不是通過。正常Main成對配置及新程序的合成輸入重開已有限定QA，但完整推薦執行／結果保存／真人與EXE旅程仍待；不能以打開月營收篩選checkbox推定已選每日cohort，原歷史模式仍依其版本證據。

Registry年度binding與上述重開／比較／返回操作已有固定`675bea26`來源／候選EXE同版的合成Main／新程序證據；其他交付仍各自依版本與收據核對。這不授真雙市場來源、PIT、完整績效或Native真人資格，詳[Increment31 QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md#increment31固定來源候選exe與registry同版旅程)。

### 選擇已接受範圍的固定月營收快照

1. 先保留既有一次性來源／用途接受紀錄與完整批次pin。由受信服務產生binding配置原件；來源接受、批次品質與版本選擇分開判定，切換下一個成功日批次不代表重新人工接受來源。
2. 在既有Baldr `config.json` 加入 `MONTHLY_REVENUE_COHORT_BINDING_PATH`（外部binding檔案的完整絕對路徑）及 `MONTHLY_REVENUE_COHORT_BINDING_SHA256`（該binding原件的64位小寫SHA-256）。兩項須一起提供；亦可由同名環境變數覆蓋。hash應由受信配置提供，不用snapshot自述hash冒充來源接受。
3. 正常啟動或新程序重開時，Main核配置、所有必要市場及固定版本後，交給同一推薦preparer/provider。部分配置、hash不符、缺市場、symlink／reparse或包內來源會拒絕；保留原檔與錯誤，核對所選版本及接受範圍，不手改hash掩蓋缺件。
4. 啟用目前月營收條件後仍須核同次決策截止時間、共同可用小時、實際資料狀態及warnings。既有無此配置的使用者維持原來源路由；這不是自動選latest、補歷史或啟用正式排程。完整來源證據與正式日常更新接線仍按[本輪QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md)判讀。

先核對 result ID、決策日、資料日、Profile、母體、quality 與 warnings，再閱讀 Why、Why Not、分數拆解及 screening matrix。`missing`、`degraded`、`skipped`、`failed` 是不同原因；有效空結果不等於來源缺失。Regime confidence、reliability 或 rule score 不是未來勝率。

按「保存結果」可把目前完成的一輪存入 canonical research source；畫面會以同一結果 ID 做讀回確認。保存失敗或 readback 未通過時不要手改 hash、複製 artifact 或把最新檔案當成同一結果。只有已保存且 verified readback 的列才能加入觀察清單或沿來源連到持倉。

「送 Research Lab 批次回測」會送候選作批次研究；「送 Research Lab 推薦回放」會用保存的 Profile／設定重播歷史決策點，研究整套推薦行為，不是只回測今天名單。回放不會自動下單或調整持倉。

## Research Lab／策略回測

Paper保存快照區需先明示外部 `PAPER_CONTRACT_ARTIFACTS_ROOT` 絕對路徑，並使用PERSONAL store；未設定或設定無效時顯示具體原因，其他Research Lab功能仍可用。展開後輸入策略、版本、帳戶命名空間及含時區截止時間，按查找列出最多200筆候選；截斷提示代表清單未列完，不自動挑選最新項目。選取所需operation／snapshot後讀回對應卡片，來源版本沿用正常策略版本選取，操作不建立或更新任何帳戶資料。

清單候選本身未驗證。快照exact讀回成功也不代表底層來源可得性、完整期間曲線或績效資格已合格；未提供指標保持空值並列明原因，不能把零成交當零報酬。關閉工作區會取消未完成讀取並拒收過期回覆；需要重新查找時重新輸入原保存身分。設定與完整步驟見[主操作手冊](../APPLICATION_MANUAL.md)，驗證界線見[本輪QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md)。

### 選模式和研究範圍

| 模式 | 用途 | 輸入範圍 |
|---|---|---|
| 單股回測 | 研究一檔股票與策略的歷史交易 | 股票代號或個股研究來源 |
| 批次股票回測 | 比較同一策略在多檔候選上的表現 | 候選池／股票清單 |
| 固定清單逐檔回測 | 查看同一清單內各檔個股的結果 | 固定股票清單；每檔獨立結果，不是共享現金組合 |
| 推薦系統回放 | 重播推薦 Profile 在各歷史決策日的候選與組合結果 | 已保存推薦設定／範圍 |
| 策略研究 | 掃描參數或做 train-test／Walk-forward 驗證 | 策略與驗證期間 |

執行前設定：策略來源、股票母體、開始／結束日期、初始資金、手續費、滑價、停損／停利、部位大小、最大持倉數與市場限制。輸入成本與金額按畫面欄位的單位填寫，保存後以 run manifest 為準。

後續開發分支的單股／逐檔回測、規則卡與 Walk-forward 使用當次選定策略的登記版本；參數掃描在讀行情前固定該輪版本，所有組合沿同一版本。基準策略目前為 `1.0`，暴衝與穩健策略為 `1.0.0`。版本缺漏、空白或互相衝突會顯示「策略版本不可用」，應重新選取有效策略，不能手改 run 或把版本補為 `1.0`。這項修正尚未納入固定 `9fa4518c` 試用包。

- 執行價格建議 `next_open`：訊號日收盤後，最早於下一可交易 session 的有效開盤成交；缺開盤、零量或停牌不回退使用收盤價。`close` 是同根 K 收盤成交假設，需在結果中明確揭露。
- 百分比停損／停利使用固定比例；ATR 模式依波動調整距離。部位方式可用全倉、固定金額或風險百分比；整股模擬以 1,000 股為單位，資金不足可能造成 0 交易。
- 最大持倉數 `0` 表示無限制，`1` 表示最多同時持有一檔。漲跌停、成交量與最大參與率會限制成交。
- 單股next-open未成交日仍保留當日收盤權益及原取消／風控處理，沿前一完成收盤核下一開盤限制。預存MACD只有原實際觀測才接計分器別名，缺值／暖機未知不補成中性。修復前舊run不改寫，新結果另執行保存。
- 交易次數為完成進出場配對；已買入但期末未平倉時可仍為0，摘要顯示「尚無已完成交易」。即時結果分列原成交筆數與期末持股，缺欄位為「未提供」；歷史頁不從零配對補造成交數。期末權益含未平倉估值，不是已實現損益或正式績效。缺分數／門檻不推論未成交原因；第一版主要驗收為正常固定門檻研究。
- 百分位門檻以決策日以前的 expanding history 為基礎；歷史暖機不足時不應產生 quantile 訊號。比較 fixed 與 quantile 時要固定資料、成本、成交假設及期間。
- Optimization 與 Walk-forward 是互斥研究模式。最佳化結果是 in-sample 候選；更換參數前先看 OOS／Walk-forward、交易數、回撤和不同期間穩定性。

### 執行、取消與結果

畫面下方唯一的主要執行按鈕會依模式顯示本輪工作內容。開始後，取消按鈕會停止提交新工作並等待已啟動任務安全收尾；不要把仍在收尾的畫面當作已取消或已完整完成。

結果檢查順序：

1. 核對 run ID／狀態、日期區間、股票母體、策略版本、成本、成交假設和 benchmark。
2. 查看摘要、交易數、coverage、最大回撤、費用、warnings，再讀 equity／drawdown 圖、交易明細與逐股結果。
3. 比較 Registry run 前先看畫面標示的「可直接比較／需謹慎比較／不可直接比較」及原因；未知欄位保持未知。
4. 「保存結果」只接受本輪成功完成且尚未被新一輪取代的結果。保存後以 Registry run ID 讀回。
5. 「升級為策略版本」須符合 Registry、驗證及 lifecycle gate。單次高報酬、最佳化排名或一份 replay 都不足以證明策略實盤有效；升級也不等於下單權限。

研究結果保存其參數、資料指紋、成本／成交假設與結果摘要；來源追加新資料不會重算原 run。保存、讀回或比較出現完整性錯誤時，先保留錯誤與 run ID，再依 owner 維運程序查詢，不手動改 Registry 或 artifact。

即時結果保存後仍可另存名稱；重開歷史結果則停用重新保存，須執行新實驗才可保存新結果。策略版本修正只影響新請求，舊 run 的原版本保持不變，不自動升級或補認證。版本一致也不表示來源、歷史 PIT、績效或升級資格已通過。

## 6.7 官方市場與技術條件研究

推薦分析的來源頁籤若提供「官方市場與技術條件研究」，它查詢已保存的研究來源，不是推薦評分或 Advice。

1. 選擇保存來源資料夾並更新來源清單，選取可核驗的保存版本後按「核驗並開啟所選保存版本」。空清單代表目前沒有可用來源。
2. 設定母體範圍、官方市場／處置狀態、指定股票代碼與技術條件，再按「套用條件並重新全域查詢」。只改控制項而未查詢，畫面不會更新結果。
3. 用上一頁／下一頁瀏覽；選股後查看保存事實與原因。加入比較籃後可比較 2–5 檔同來源結果。
4. 「準備研究收藏」成功後，到「觀察清單」選取並重開；重開時會核驗原來源身份，不會改用最新來源補缺件。

| 條件 | 判讀方式 |
|---|---|
| 母體列範圍、官方市場／處置、指定代碼 | 先限制保存母體；指定代碼須勾選「只查指定代碼」。 |
| 技術條件、四均線、KDJ | 依保存狀態判斷；不符合、未知與缺資料分開。 |
| Bandwidth、ATR14 SMA 範圍 | 單位是百分比；空白表示不設該側界限，不表示 0。 |
| 規則與群組 AND／OR、未知政策 | 分別控制規則間、條件群組如何合併以及未知列如何處理。 |
| 全母體排序、每頁列數 | 排序作用於完整查詢結果；每頁可設 1–256 列。 |

來源覆蓋、聲明母體、納入數與目前頁面列數不同。若來源標示 `current_only`、coverage 不完整或 available time unknown，研究收藏不會把它提升成歷史 PIT 或正式訊號。這項研究只供保存來源比較，不產生獲利機率或交易指令。

## 已保存來源與完整母體研究

在「推薦分析」的結果來源分頁，可依研究目的選擇「每日研究條件」、「官方市場／處置研究」、「四均線／官方對照研究」、「均線／月營收／官方對照研究」、「官方市場與技術條件研究」或新增的「官方條件與價格研究」。每日研究頁包含每日快照、技術完整母體（Union）和價格研究區塊；往下捲到目標區塊後再操作。各頁讀取不同保存 schema，不能把一頁的列當作另一頁的來源。

### 官方條件與價格研究

每日研究頁中既有的價格研究區塊，在窄結果區將價格上下限、規則篩選及比較操作直向排列。往下捲動到「套用條件」再執行；視窗縮放保留原輸入及來源，不會自動重新查詢。這項排列不改變下列官方複合研究的來源或用途要求。

此頁是目前補完候選的研究入口；驗證與尚未完成的交付範圍依[本輪QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md)，不代表來源、歷史PIT或交易資格已接受。

1. 指定自己的已保存來源資料夾，更新清單並明選版本，再開啟核驗。缺件或hash不符時保留錯誤，不改開最新版本。
2. 設定技術、四均線、KDJ與波動的四組條件及AND／OR，再設定獨立的收盤價上下限、各邊界含或不含，以及未知價格的納入／排除／只看未知。金額使用正數Decimal；空白表示未設定，反向範圍或非有限數會拒絕。價格條件在四組結果後作共同AND，不加入四組OR。
3. 查看完整母體分母、四組原結果、價格已知／未知及最終可見數。全域排序先於分頁；收盤價未知值置尾，等值以股票代碼升冪固定次序。每頁最多256列是頁長，完整母體可以超過256檔。
4. 選列查看原保存事實，或把同一結果內2–5檔加入比較籃。跨頁比較、返回及收藏沿同一query／result／pins；重新套用條件後不要把舊列當成新結果。
5. 準備收藏後由正常Watchlist路徑保存，再從該收藏列開啟研究。收藏含價格邊界、未知政策、排序、頁、選股、比較籃與捲動偏好；重開重新核對指定來源。忙碌、缺件、錯版本或畫面無法完整呈現的外部多排序鍵會拒絕，保留具體原因。

四組未知政策與未知價格政策各自生效。官方可得時間未知、current-only及歷史PIT不適用的狀態保持；收藏不會替來源補資格。「高／中／低價」尚無定版區間時，以實際上下限判讀。新程序精確恢復及同版EXE是否完成，仍以具名QA為準。

1. 在來源頁明確選資料夾或保存版本。按「更新來源清單」只列出候選；接著選取目標版本並按頁面提供的核驗／查詢按鈕。來源 pins、保存日期、母體與 warnings 通過後，才用該查詢結果。
2. 在技術完整母體頁設定 AND／OR、股票代碼、規則、全域排序與方向，再按「套用全域查詢」。空白股票代碼表示查完整個已保存母體；指定股票只縮小原母體。篩選與排序先作用於完整母體，之後才分頁；每頁列數可選 25、50、100 或 256。
3. 選取來源列後按「讀取原保存個股證據」；技術 Union 比較籃需 2–256 檔，官方市場與技術條件頁比較籃需 2–5 檔。取消背景工作或回傳身份不符時保留原查詢，不採用未核驗列。
4. 按「收藏目前查詢與比較籃」或該頁相應收藏按鈕，按畫面狀態完成保存；再到「觀察清單」選取收藏並重開。重開會核原來源、條件與選取股票；來源已變動時應重新選取及核驗，不能改用最新版本補上舊結果。

這些來源頁的查詢和讀回不會自動跑 producer。頁面上如另有「產製技術與官方來源研究」，那是明示的研究產生工作，與更新 catalog 或讀取已發布快照不同。若外部來源被標為唯讀，產製／續跑可能停用；不要改用另一個來源 root 解鎖。若 available time 未知、scope 不完整或母體身份未核，保留 unknown；研究頁的排名、比較與收藏都不因此成為 PIT、推薦 Advice 或正式訊號。詳細來源 pin、跨頁返回與 store 路由契約見[目前應用架構](../../01_architecture/current/application_and_workspaces.md)與[目前資料儲存架構](../../01_architecture/current/data_storage_runtime.md)。

## 個人 H20 保存研究

「推薦分析 → 個人模型選股研究（H20毛報酬）」讀取已保存的完整 H20 母體。開啟分頁時會核驗原保存來源；也可按「讀取每日已保存模型名單」重讀。若頁面仍在讀取，等狀態返回；要取消時按「取消名單讀取」並等安全收尾。取消或核驗失敗不會把部分名單當成有效，也不會用另一個 cycle 替代；完整錯誤與來源身份可在頁面選取、複製。

名單只列原 manifest 成員，欄位包含股票、H20 毛報酬（bp）、狀態、決策日、來源日、特徵截至日與原因。排序只改同一原 manifest 的列順序，不是全市場排名。選「可核原預測」列後按「研究選取股票」或雙擊，進入沿原 H20 來源的個股研究；按「收藏原保存 H20 研究」則保存該版本身份，之後從觀察清單精確重開。未知列會停用研究／收藏操作；不要以另一檔股票、另一個日期或重算值代替。

H20 是未扣成本的 20 交易日毛報酬估計，不是勝率或機率，也不代表模型有效、自然結果已成熟或值得買進。個股報告中的 H20、H5 成本後超額與一般最新行情是不同投影；若原保存 H20 沒有綁定同版本價格／技術圖表，不會由一般報告補造。若畫面提示沒有安全副本目錄，讀取尚未開始；依首次安裝／移機流程由 owner 核對 H20 來源與安全副本設定，不要任意改根目錄或複製模型資料。

目前 UI 與來源 reader 可在 `ui_qt/main.py`、`ui_qt/widgets/personal_h20_research_widget.py`、`app_module/recommendation/personal_h20_verified_cohort_view.py` 及 `scripts/scheduled/personal_h20_daily_hook.py` 查閱。存在讀取入口不等於個人模型通過自然成熟、品質或產品 Gate；整體現況看[目前狀態快照](../../00_core/PROJECT_SNAPSHOT.md)，具名 QA 收據仍只說明其記錄的版本與範圍。

### Immutable ML artifact 保留界線

一般使用者不應清理、搬移或改寫 release、ML manifest、latest pointer 或其 lineage。現行 `scripts/inspect_ml_storage_retention.py` 只提供唯讀 metadata inventory，並沒有 destructive retention runbook；需由 owner 依[資料儲存架構的保留與核准邊界](../../01_architecture/current/data_storage_runtime.md#immutable-ml-retention-的目前檢視與核准邊界)處理。歷史 Supplements 內的 retention 命令與 QA 不是目前可執行步驟或授權。

## 常見問題

- 沒有候選：先看資料日、可評估母體和缺少的啟用指標，再確認篩選條件。降低門檻不能修復缺行情或缺欄位。
- 回測 0 交易：檢查日期、資金、整股 1,000 股限制、成交量及參與率；0 筆不必然表示策略沒有訊號。
- 參數最佳化很好看但結果不穩：in-sample 排名不是驗證；做 OOS／Walk-forward 並確認樣本足夠。
- 保存結果讀回失敗：保留 run ID 與狀態；不要刪除 artifact、複製舊檔或修改身份欄位。
- 校準候選或 shadow 模型保存／讀回失敗：保留同輪 run ID、來源身份、完整錯誤與 lineage 狀態，交由 owner 依 [ML Shadow 維運 Runbook](../ML_SHADOW_INFERENCE_OPERATIONS_RUNBOOK.md)核對。不要改 hash、改用另一輪 artifact 或手動啟用模型；校準套件的 Windows 長路徑修正不代表所有來源 root 或工作流程都已驗證。

其他推薦回放、模型 shadow、natural maturity 與 Evidence 維運契約見 [全排程唯讀稽核 Runbook](../BALDR_SCHEDULED_AUDIT_RUNBOOK.md)及[目前狀態快照](../../00_core/PROJECT_SNAPSHOT.md)。

一般單股／批次回測保存到 Registry 時，曲線須帶 producer 實際逐列日期；缺日、重複、亂序或模糊日期會拒絕保存。請保留具名錯誤並核對來源，不用 requested 起訖日或最新行情補造曲線日期。新保存會保留原日期，較早缺日 run 的期間比較仍受限；日期齊全也不代表已接受損益／幣別／成本或兩策略全期間績效。

### 已保存單股 next-open 精確觀察的讀回（2026-10-14）

新的單股 next-open 結果會把原精確觀察與版本資訊一起保存到Research Run Registry。從既有Registry開啟後，結果為唯讀；原資料、策略版本或附件不符會拒絕，保留原畫面，不重跑回測。舊V1保存結果維持原讀法，不從圖表金額補造精確帳本。

本輪next-open保存同時保留當時提交的手續費／滑價／交易稅與lot，以及實際採用值或具名policy內容；未指定與明示0不合併。重開讀回同一輸入，不使用目前設定替換；較早run缺這些欄位時不補造。這只是原執行輸入的保真保存，不能據此認定成本規則、行情幣別或來源已獲接受。附件損毀、身份不符或超過讀取上限時拒讀，保留run ID與錯誤，不手動改附件。

「producer完成」只代表該次實際迴圈走完，不代表日曆或期間coverage完整。策略或具名成本身份缺失仍能保留觀察，但無period precision；來源、幣別、日曆未具證據時不可拿此結果作可排名的績效比較。取消只有已產生的partial列，不補剩餘日期；每日實現／未實現盈虧未新增推算。

較早隔離驗證只覆蓋writer與直接opener；Increment20另驗正常Main保存按鈕／對話框、Registry列表重開、雙run診斷、返回與新程序。仍用合成資料，不授完整雙策略績效、正式來源或Native／EXE資格。各輪結果見[本輪QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md)。

### Registry 雙 run 完整期間診斷

1. 兩次獨立推薦回放完成後，各按「保存推薦回放」、填名稱並確認；記下原 Registry run ID。歷史讀回結果不可重存，可沿原 run 重開。
2. 在「研究 Registry」選既有推薦回放，按原開啟按鈕核對完整結果，再回 Registry。通用 2–5 筆比較沿原規則；完整期間診斷須恰選兩筆不同的推薦回放。
3. 「完整期間日曆版本」明選來源模式。「保存原件」填原件絕對路徑與該版保存收據的64碼小寫SHA-256；「每日批次」填已完成批次的絕對目錄、manifest SHA-256與成功收據SHA-256，且須顯示已配置的TWSE／TPEx獨立來源用途接受紀錄。再明選市場並按「固定日曆版本」。不會抓取日曆，不自算目前檔案hash取代外部收據，也不從批次內容自建接受紀錄。
4. 按「比較完整期間」。背景核對兩筆 metadata、原附件、replay child 與同一日曆版本；畫面列 run／parent／策略版本、預期與實際日期、缺日、非預期日期與具名阻擋。日期覆蓋完整與績效資格分開判讀；候選日曆或來源／幣別／成本未知仍阻擋，指標保持空值。
5. 後續開發分支在下方逐日原觀測明細分列左右股票、現金、持倉估值、權益及原件有提供的已實現／未實現損益。日期使用兩run實際觀測的聯集，每頁最多100日，按「上一頁原觀測／下一頁原觀測」換頁；不重新讀來源或重算結果。「無觀測」是該run缺該日，「未提供」是原件未提供欄位，兩者皆不是0。各側本金／期間／完成狀態與幣別分開看，未核幣別不視為相同單位；不可把兩策略金額相加或當作可排名績效。此增量尚未納入固定9fa第一版試用包。
6. 「返回所選 run」回清單並保留兩筆選取。換選取、改日曆或開始新研究清除舊配對。可按「取消完整期間讀取」，等待安全收尾；關閉亦合作取消，過期回覆不套用。
7. 重開程式後重新選原兩個run ID，重新指定同一來源模式、原件收據或批次雙SHA、市場與獨立接受紀錄。每日批次每次固定使用當下真實讀取時間，保留該次cutoff；成功批次可用小時尚未到則拒讀，不提供時間改寫欄位。缺件、hash不符或metadata修訂時保留錯誤與收據，不補latest、不手改附件或補造歷史資料。

目前每日批次接線只有隔離合成資料的正常Main／新程序證據；正式Main尚未配置真來源用途接受紀錄，保持停用。看到缺少接受紀錄時保留該原因，由資料owner先完成官方文件鏈與用途核對，不把manifest、HTTP Date或候選解析成功當成接受。

年度來源批次沿相同欄位與步驟讀回，由已配置的兩市場接受紀錄固定年度或月別家族；不可把其中一個市場換成另一家族的接受紀錄，也不可用年度manifest搭月別receipt。年度股票來源會區分交易與僅結算，債券日期不套用股票。年度保存／public reader／真控制器與正常Main／新程序已以合成接受限定驗證；不外推真來源用途接受。

資料owner可另提供已核用途接受的固定配置檔與獨立SHA，將`CALENDAR_DAILY_ACCEPTANCE_BINDING_PATH`／`CALENDAR_DAILY_ACCEPTANCE_BINDING_SHA256`成對放入現行環境或GUI的config.json，再重開Main。檔案須在正式資料、輸出與程式包之外；只固定接受紀錄，批次目錄及雙SHA仍按上列步驟選取。配置超界、漂移、錯SHA或來源混搭時daily比較停用，保留具名原因；先核owner提供的原配置與外部收據，不用目前檔案自算hash取代它。切來源模式不清除該配置錯誤；更正配置後重開程式，已開視窗不自動換版。年度合成Main／fresh已完成兩run重開／比較／返回；真接受決策、正式配置與Native／EXE仍獨立。

日曆候選每份 evidence 最多涵蓋首尾含在內 93 日，原件／附件亦有 byte budgets。超界需 owner 依完整版本契約處理，不能自行拼接宣稱任意長期間已接受。此入口不授官方用途、歷史 PIT、完整雙策略績效或交易資格；證據見[Increment20 QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md#increment20恢復後reader與正常registry旅程)。
### 每日月營收版本選擇（2026-10-14）

自然決策首次需要月營收時，程式會在本次決策時間以前、已成功完成且保存的版本中選取快照；本次所有股票固定使用同一組雙市場版本。稍後發布的新批次供新的決策使用。可用小時不得早於實際取得，例如14:45完成按15:00使用；沒有官方發布小時的來源會明示成功批次依據。版本、單位、必要市場或原件檢查失敗時，本次資料不可用並留下原因，不改用未核的舊讀法。
