# 推薦與 Research Lab

「研究 Registry」另有「配置研究紀錄（非回測績效）」：情境須先在持倉管理保存並明確登錄；輸入帳種與完整 portfolio_id、載入後明選一筆，按「開啟所選紀錄」回到原配置研究封存。這類紀錄不加入回測多選比較或 promotion，也不補本金、績效或 equity/trades；登錄時間不是原資料可得時間。步驟及原件缺失／版本錯誤排錯見[登錄研究指南](WATCHLIST_AND_PORTFOLIO.md#登錄研究紀錄與跨頁重開)。此為後續開發分支功能，固定 `4b530a7e` 試用包不含。

本手冊說明如何建立研究候選、保存一輪推薦、做歷史回放與解讀回測。每次先確認股票母體、決策日、行情資料日、成本／成交假設和來源品質。歷史研究只使用決策當時可取得的資料；可讀的模型投影、回放或一次高報酬都不是自然證據或實盤績效。

從後續開發分支「配置研究封存」進入個股時，持倉分頁顯示該已保存情境的原帳戶及 targets，不查今日同股手動持倉。比較預覽須先另存；原 mark 時間缺件不以帳戶時間替代。操作、錯誤及返回見[配置研究指南](WATCHLIST_AND_PORTFOLIO.md#配置研究封存與另存假設)，完整初始來源與 P06 仍待，固定試用包不含此後續增量。

## 推薦分析

### 建立一輪候選

1. 查看頁面上的市場狀態、資料日、來源與 warnings。
2. 新手模式可選一個內建 Profile，或套用系統提示的 Profile；先讀對應的權重與篩選說明。自訂 Profile 會標示未經回測驗證；策略版本 Profile 只表示它符合該版本既有選用條件，不代表實盤驗證。
3. 進階模式可調整技術指標、圖形模式、最小漲幅、最小成交量比率、產業、評分門檻，以及可選的月營收 YoY／PE 條件。啟用的指標必須有足夠歷史資料和合法參數，缺值不會補成零分。
4. 選擇固定門檻或百分位排名，確認 eligible universe、最小母體數與 top-N，再按「執行推薦分析」。

設定解讀：

- `pattern`、`technical`、`volume` 權重以整數基點表示，總和必須為 10,000 bp。buy／sell score 是結果判讀門檻；改門檻不會改變各指標如何貢獻分數。
- 啟用月營收或 PE 篩選時，既有歷史版本仍按 `available_date <= decision_date` 判定；明示pinned每日快照另核台北小時可用性與含時區截止時間，發布時間與成功批次時間向上取整，不提前使用。基本面缺件會留在screening matrix，不能用目前最新資料填入歷史決策；此政策不表示正常UI每日批次入口已完成，詳[資料與市場研究](DATA_AND_MARKET_RESEARCH.md)。
- 固定門檻使用既有絕對門檻；百分位依當日 eligible universe 排名，會受最小母體數與前置條件影響。quantile 維持 opt-in，不能只因排名靠前便宣稱優於 fixed。
- 「取消分析」是合作式取消。等待安全收尾期間不會套用不完整結果，上一筆完整結果會保留。

### 閱讀結果與保存

由已核驗composition明示使用每日cohort時，上市／上櫃各自綁批次與原件；所有必要市場都成功後，以較晚小時判定整組可用。同次推薦來源追溯會帶cohort hash/pin及各股實際讀取狀態；missing／unknown仍是缺件，不是通過。正常Main成對配置及新程序的合成輸入重開已有限定QA，但完整推薦執行／結果保存／真人與EXE旅程仍待；不能以打開月營收篩選checkbox推定已選每日cohort，原歷史模式仍依其版本證據。

Registry年度binding與上述重開／比較／返回操作已有固定`675bea26`來源／候選EXE同版的合成Main／新程序證據；其他交付仍各自依版本與收據核對。這不授真雙市場來源、PIT、完整績效或Native真人資格，詳[Increment31 QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md#increment31固定來源候選exe與registry同版旅程)。

### 選擇已接受範圍的固定月營收快照

1. 先保留既有一次性來源／用途接受紀錄與完整批次pin。由受信服務產生binding配置原件；來源接受、批次品質與版本選擇分開判定，切換下一個成功日批次不代表重新人工接受來源。
2. 在既有Baldr `config.json` 加入 `MONTHLY_REVENUE_COHORT_BINDING_PATH`（外部binding檔案的完整絕對路徑）及 `MONTHLY_REVENUE_COHORT_BINDING_SHA256`（該binding原件的64位小寫SHA-256）。兩項須一起提供；亦可由同名環境變數覆蓋。hash應由受信配置提供，不用snapshot自述hash冒充來源接受。
3. 正常啟動或新程序重開時，Main核配置、所有必要市場及固定版本後，交給同一推薦preparer/provider。部分配置、hash不符、缺市場、symlink／reparse或包內來源會拒絕；保留原檔與錯誤，核對所選版本及接受範圍，不手改hash掩蓋缺件。
4. 啟用目前月營收條件後仍須核同次決策截止時間、共同可用小時、實際資料狀態及warnings。既有無此配置的使用者維持原來源路由；這不是自動選latest、補歷史或啟用正式排程。完整來源證據與正式日常更新接線仍按[本輪QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md)判讀。

先核對 result ID、決策日、資料日、Profile、母體、quality 與 warnings，再閱讀 Why、Why Not、分數拆解及 screening matrix。`missing`、`degraded`、`skipped`、`failed` 是不同原因；有效空結果不等於來源缺失。Regime confidence、reliability 或 rule score 不是未來勝率。

按「保存結果」可把目前完成的一輪存入 canonical research source；畫面會以同一結果 ID 做讀回確認。保存失敗或 readback 未通過時不要手改 hash、複製 artifact 或把最新檔案當成同一結果。只有已保存且 verified readback 的列才能加入觀察清單或沿來源連到持倉。

「送 Research Lab 批次回測」會送候選作批次研究；「送 Research Lab 推薦回放」會用保存的 Profile／設定重播歷史決策點，研究整套推薦行為，不是只回測今天名單。回放不會自動下單或調整持倉。

## Research Lab／策略回測

Paper保存快照區需先明示外部 `PAPER_CONTRACT_ARTIFACTS_ROOT` 絕對路徑，並使用PERSONAL store；未設定或設定無效時顯示具體原因，其他Research Lab功能仍可用。展開後輸入策略、版本、帳戶命名空間及含時區截止時間，按查找列出最多200筆候選；截斷提示代表清單未列完，不自動挑選最新項目。選取所需operation／snapshot後讀回對應卡片，來源版本沿用正常策略版本選取，操作不建立或更新任何帳戶資料。

清單候選本身未驗證。快照exact讀回成功也不代表底層來源可得性、完整期間曲線或績效資格已合格；未提供指標保持空值並列明原因，不能把零成交當零報酬。關閉工作區會取消未完成讀取並拒收過期回覆；需要重新查找時重新輸入原保存身分。設定與完整步驟見[主操作手冊](../APPLICATION_MANUAL.md)，驗證界線見[本輪QA](../../06_qa/BALDR_DATA_POLICY_IMPLEMENTATION_20261014.md)。

### 已保存策略版本與來源研究（後續開發分支）

此入口只讀已存在的StrategyVersion與其原研究，沒有新增升級或重跑動作；目前為source功能，固定`0f644faa0d48`預覽與舊4b530／9fa包均未含此增量。

1. 在「策略回測」收合左側設定，展開結果區的「已保存策略版本（版本聲明／來源研究）」。
2. 按「刷新保存版本」；每頁最多200份，使用「上一頁版本／下一頁版本」找較早紀錄。清單沒有自動挑選最新版本。
3. 明選一筆，核對保存版號、來源run執行版號、策略、來源與保存狀態聲明。兩個版號可不同，例如保存1.9.3連到執行器1.0.0，不能手動改成相同。
4. 按「查看原執行規則」沿原保存規則卡核對；關閉卡片後，按「開啟原研究結果」查看原曲線／交易，保存按鈕維持停用。舊來源缺收據時沿原卡片的缺件／不可評原因，不補目前規則。
5. 切換其他工作區再返回，或重開後沿同一版本／run重新查找；若版本或來源在選取後變動，先保留原因，再明確刷新選取，不自動改開另一份結果。

空清單表示尚無已保存版本；仍可用原「研究歷史查找」看run，不能為填滿清單而放寬promotion。來源非Registry、run缺失、metadata-only或交叉欄位不符時保留診斷並停用開啟；取消／背景收尾時先等待原工作完成。保存狀態如pending／validated是檔內聲明，版本JSON本身仍可變，不代表歷史不可變、PIT、正式績效或交易資格。執行器版本、資料日期及成本以原run核驗結果為準，沒有搬移舊版本或改寫原結果。

後續source分支的新建版本使用獨立ID；同一秒保存兩次不取代前版，明確指定重複ID會失敗。遇到磁碟／權限／flush錯誤時保留原錯誤，未完成暫存不列為保存版本，也不要手動改ID或刪原JSON來重試。晉升若在Registry回填後或生命週期紀錄階段失敗，已保存JSON保留供核對；可寫入的狀態標為`reconciliation_required`，原核對掃描會列出。這種狀態須保留run ID、版本ID及錯誤交由維運核對，不能當作晉升成功；若連狀態寫入都失敗，log仍保留原錯誤，單看`synced`不足以證明生命週期紀錄完整。沒有自動修復舊版本、重試晉升或取得交易資格，固定0f644faa／4b530／9fa包未含此修正。

### 布林基礎突破研究（後續開發分支）

原策略清單新增「布林基礎突破（研究）」`1.0.0`，固定使用30期、2倍SMA布林通道。它研究首次向上突破上軌、跌破中軌出場的自有假說；不含壓縮、量能、VCP或共振條件，也沒有取得來源／歷史PIT或績效資格。固定`0f644faa0d48`預覽及舊4b530／9fa包尚未包含。

1. 在「策略回測」選這個策略、股票及期間，查看「策略規則說明」。只有「突破連續確認交易列」1／2／3可選，預設1；不是綜合分數門檻。2／3列須由新突破開始連續高於各日上軌，確認日才發進場意圖，不能回標第一天。
2. 使用`next_open`、不加碼與百分比風控，照原欄位設定本金、費率、滑價、部位、停損停利和成交限制。close或ATR風控路由會被拒絕，重新選支持的設定，不會默默忽略。
3. 按原執行按鈕；正常入口同次只讀前180曆日、最多留31筆前置觀測供暖機／前日比較。缺件會重暖機、不填值；測試窗不繼承前段確認或持倉，績效期間仍是所選實際期間。
4. 看「布林規則診斷」的可用／不可用觀測、進場訊號與出場條件日數，再核成交明細／完成配對。訊號不是成交；原漲跌停、缺開盤、零量、資金與股數限制可能延後或拒絕成交，不能為取得交易而取消守衛。
5. 用原「保存結果」，再到歷史清單明選同一run，按「查看保存規則」及「開啟原結果」。改目前確認日數不改保存規則；切頁返回或新程序仍讀同次訊號、規則、成本與來源。保存策略版本清單同樣可沿原入口回到該run。

收盤等於上軌不是新突破，已在軌外不每天重發進場；等於中軌保持。中軌出場／原風控之外沒有固定持有日數，期末未平倉只估值。新版本只允研究保存，即使SOP單項滿足也不能正式晉升；來源／PIT、OOS／Walk-forward與自然成熟要各自完成。1／2／3確認的敏感度檢查只驗訊號差異，不挑結果較好的設定宣稱有效。來源、版本、日期、成本或保存訊號錯配時拒絕開原規則；不要手改原JSON／run或借今天參數補值。

目前只驗收上述正常單股研究旅程；批次、參數研究與Walk-forward等其他模式尚未驗收，不能由這條旅程推定已完成。

### W底頸線突破研究（後續開發分支）

在「策略回測」選「W底頸線突破（研究）」`1.0.0`。這是自有的收盤價三點谷／頸線突破假說；第二谷須等右一列收盤才確認，之後實際突破凍結頸線才發進場意圖，跌回該頸線發出場意圖。不改舊全段形態圖形，不授已驗有效或歷史PIT；固定`0f644faa0d48`預覽及舊4b530／9fa包尚未包含。

1. 選單股代碼、研究期間，打開原「策略規則說明」核兩谷、前置跌勢、頸線及失效規格。只可選「第二谷確認後最多等待觀測列」5／10／20，預設20；這是等待新突破的期限，不是持有天數，也不是分數門檻。
2. 使用`next_open`、不加碼與原百分比風控，明示本金、費率、滑價、部位與交易限制；close或ATR停損／停利路由會被拒絕。缺少可證行情不補值，測試窗內重新累積形態，不帶訓練段候選或意圖。
3. 正常執行後看「W 底規則診斷」：可判讀列、不可判讀列及進出場意圖。不可判讀含暖機、缺資料和失效重啟；幾何符合、訊號意圖、實際成交及完成配對分開看，零量／停牌／缺開盤／漲跌停可能延後或拒絕成交。
4. 用原「保存結果」，再在歷史清單選同一run，開「查看保存規則」及「開啟原結果」。保存的是當次凍結的等待值、規則、成本、確認日與逐日訊號；保存前改畫面參數也不改原結果。若需不同假說，明確重跑並另存。
5. 切頁返回或重開程式，仍選同一run；也可沿「已保存策略版本」明選來源研究。保存生命週期版與原執行器版分開顯示，不以目前Registry或新參數補歷史。

來源內的兩谷日只作幾何證據，確認日與實際進場意圖日不可回標。等於頸線保持；缺行情期間已有意圖保留原頸線、當列不造出場。沒有固定持有天數或強制期末出售；實際部位與原Broker停損停利各自判斷，episode不自認成交。

請求期間比可用行情寬時，保存／歷史按實際資料窗判讀，原請求保留供追溯。若保存出現「來源輸入不一致」或版本／日期／成本錯配，保留錯誤與run ID，不手改JSON／版本檔；回到原結果核對或明確重新執行。取消與來源缺件不算完成保存。即使完成配對數達SOP最低樣本，也不能正式晉升；來源／歷史PIT、OOS／Walk-forward、Paper與自然成熟仍各自未合格。目前只驗上述正常單股旅程，其他模式與Native／EXE尚未驗收。

### 選模式和研究範圍

後續開發分支新增兩個既有策略的保存規則讀回：選穩健或暴衝策略、固定門檻及 `next_open`，照常執行並保存；展開結果中的歷史清單，選取同一 run，按「查看保存規則」，再按「開啟原結果」回看原結果。規則卡顯示當次實際門檻、確認天數、成本、風控與來源，關閉後保留選取，切頁返回或重開程式仍讀同一保存版本。改目前參數不改歷史規則；基準策略仍沿原 v1，舊結果及其他模式不補新來源。

「原執行的規則、成本與來源已核對」只表示保存內容一致，績效與正式資格仍不可評；錯版本、來源或成本不一致時保留原因，不用目前設定補值。停損／停利以當次保存的精確比例為準，不手改舊結果欄位。固定 `9fa4518c`、`4b530a7e` 及 `50ddb640` EXE 均未含此增量。

| 模式 | 用途 | 輸入範圍 |
|---|---|---|
| 單股回測 | 研究一檔股票與策略的歷史交易 | 股票代號或個股研究來源 |
| 批次股票回測 | 比較同一策略在多檔候選上的表現 | 候選池／股票清單 |
| 固定清單逐檔回測 | 查看同一清單內各檔個股的結果 | 固定股票清單；每檔獨立結果，不是共享現金組合 |
| 推薦系統回放 | 重播推薦 Profile 在各歷史決策日的候選與組合結果 | 已保存推薦設定／範圍 |
| 策略研究 | 掃描參數或做 train-test／Walk-forward 驗證 | 策略與驗證期間 |

執行前設定：策略來源、股票母體、開始／結束日期、初始資金、手續費、滑價、停損／停利、部位大小、最大持倉數與市場限制。輸入成本與金額按畫面欄位的單位填寫，保存後以 run manifest 為準。

後續開發分支的單股／逐檔回測、規則卡與 Walk-forward 使用當次選定策略的登記版本；參數掃描在讀行情前固定該輪版本，所有組合沿同一版本。基準策略目前為 `1.0`，暴衝與穩健策略為 `1.0.0`。版本缺漏、空白或互相衝突會顯示「策略版本不可用」，應重新選取有效策略，不能手改 run 或把版本補為 `1.0`。這項修正尚未納入固定 `9fa4518c` 試用包。

- 執行價格建議 `next_open`：訊號日收盤後，最早於下一可交易 session 的有效開盤成交；缺開盤、零量或停牌不回退使用收盤價。`close` 是同根 K 收盤成交假設，需在結果中明確揭露。
- 百分比停損／停利使用固定比例；ATR 模式依波動調整距離。部位方式可用全倉、固定金額或風險百分比；整股模擬以 1,000 股為單位，資金不足可能造成 0 交易。
- 最大持倉數 `0` 表示無限制，`1` 表示最多同時持有一檔。漲跌停、成交量與最大參與率會限制成交。
- 單股next-open未成交日仍保留當日收盤權益及原取消／風控處理，沿前一完成收盤核下一開盤限制。預存MACD只有原實際觀測才接計分器別名，缺值／暖機未知不補成中性。修復前舊run不改寫，新結果另執行保存。
- 交易次數為完成進出場配對；已買入但期末未平倉時可仍為0，摘要顯示「尚無已完成交易」。即時結果分列原成交筆數與期末持股，缺欄位為「未提供」；歷史頁不從零配對補造成交數。期末權益含未平倉估值，不是已實現損益或正式績效。缺分數／門檻不推論未成交原因；第一版主要驗收為正常固定門檻研究。
- 百分位門檻以決策日以前的 expanding history 為基礎；歷史暖機不足時不應產生 quantile 訊號。比較 fixed 與 quantile 時要固定資料、成本、成交假設及期間。
- Optimization 與 Walk-forward 是互斥研究模式。最佳化結果是 in-sample 候選；更換參數前先看 OOS／Walk-forward、交易數、回撤和不同期間穩定性。

### 執行、取消與結果

畫面下方唯一的主要執行按鈕會依模式顯示本輪工作內容。開始後，取消按鈕會停止提交新工作並等待已啟動任務安全收尾；不要把仍在收尾的畫面當作已取消或已完整完成。

結果檢查順序：

1. 核對 run ID／狀態、日期區間、股票母體、策略版本、成本、成交假設和 benchmark。
2. 查看摘要、交易數、coverage、最大回撤、費用、warnings，再讀 equity／drawdown 圖、交易明細與逐股結果。
3. 比較 Registry run 前先看畫面標示的「可直接比較／需謹慎比較／不可直接比較」及原因；未知欄位保持未知。
4. 「保存結果」只接受本輪成功完成且尚未被新一輪取代的結果。保存後以 Registry run ID 讀回。
5. 「升級為策略版本」須符合 Registry、驗證及 lifecycle gate。單次高報酬、最佳化排名或一份 replay 都不足以證明策略實盤有效；升級也不等於下單權限。

研究結果保存其參數、資料指紋、成本／成交假設與結果摘要；來源追加新資料不會重算原 run。保存、讀回或比較出現完整性錯誤時，先保留錯誤與 run ID，再依 owner 維運程序查詢，不手動改 Registry 或 artifact。

即時結果保存後仍可另存名稱；重開歷史結果則停用重新保存，須執行新實驗才可保存新結果。策略版本修正只影響新請求，舊 run 的原版本保持不變，不自動升級或補認證。版本一致也不表示來源、歷史 PIT、績效或升級資格已通過。

## 個人 H20 保存研究

「推薦分析 → 個人模型選股研究（H20毛報酬）」讀取已保存的完整 H20 母體。開啟分頁時會核驗原保存來源；也可按「讀取每日已保存模型名單」重讀。若頁面仍在讀取，等狀態返回；要取消時按「取消名單讀取」並等安全收尾。取消或核驗失敗不會把部分名單當成有效，也不會用另一個 cycle 替代；完整錯誤與來源身份可在頁面選取、複製。

名單只列原 manifest 成員，欄位包含股票、H20 毛報酬（bp）、狀態、決策日、來源日、特徵截至日與原因。排序只改同一原 manifest 的列順序，不是全市場排名。選「可核原預測」列後按「研究選取股票」或雙擊，進入沿原 H20 來源的個股研究；按「收藏原保存 H20 研究」則保存該版本身份，之後從觀察清單精確重開。未知列會停用研究／收藏操作；不要以另一檔股票、另一個日期或重算值代替。

H20 是未扣成本的 20 交易日毛報酬估計，不是勝率或機率，也不代表模型有效、自然結果已成熟或值得買進。個股報告中的 H20、H5 成本後超額與一般最新行情是不同投影；若原保存 H20 沒有綁定同版本價格／技術圖表，不會由一般報告補造。若畫面提示沒有安全副本目錄，讀取尚未開始；依首次安裝／移機流程由 owner 核對 H20 來源與安全副本設定，不要任意改根目錄或複製模型資料。

目前 UI 與來源 reader 可在 `ui_qt/main.py`、`ui_qt/widgets/personal_h20_research_widget.py`、`app_module/recommendation/personal_h20_verified_cohort_view.py` 及 `scripts/scheduled/personal_h20_daily_hook.py` 查閱。存在讀取入口不等於個人模型通過自然成熟、品質或產品 Gate；整體現況看[目前狀態快照](../../00_core/PROJECT_SNAPSHOT.md)，具名 QA 收據仍只說明其記錄的版本與範圍。

一般使用者不應清理、搬移或改寫 release、ML manifest、latest pointer 或其 lineage。現行 `scripts/inspect_ml_storage_retention.py` 只提供唯讀 metadata inventory，並沒有 destructive retention runbook；需由 owner 依[資料儲存架構的保留與核准邊界](../../01_architecture/current/data_storage_runtime.md#immutable-ml-retention-的目前檢視與核准邊界)處理。歷史 Supplements 內的 retention 命令與 QA 不是目前可執行步驟或授權。
