## 0. 核心交付原則（不可退讓）

1. **Product first, evidence later—but safety now**：先完成「完整導航／已有能力整合／每天可使用／V2 版本驗收」；歷史 PIT 大規模回補、全來源權威、全市場財報與法人覆蓋、自然 Forward 成熟、ML Promotion 等**長期資格工作列為後續獨立工作流**。未完成某項長期證據，**只隔離受影響的功能，不停止無關的 UX／版本里程碑**。
2. **金融安全立即生效**：不准將未知填零、沒有單位與可得時點的值當成有效金融結論；不繞過來源／PIT／Decimal／成本／帳本／寫入鎖；隔離研究結果不等同可發布正式推薦。這些是每次改動的必要安全回歸，不屬於可延後的長期證據蒐集。
3. **重用勝過重寫**：先整理 Main 入口、Application DTO／既有服務、共用操作，再考慮局部抽取適配器；不建立平行第二套 Journal、選股來源、財報 reader、Portfolio 帳本或 target-only package。
4. **完整功能保存**：每個現有 widget／callback 有具名新位置、共用捷徑或具名停用決定；不可為了減少 Tab 悄悄刪除能力。
5. **原始資料權威仍在原處**：此規格只管資訊架構／UX／必要 read model。金融算法、資料用途、正式 Gate、交易權限的既有契約不被此文覆寫；`PROJECT_SNAPSHOT.md` 與真實 Git HEAD 仍是 current 狀態依據。
6. **Python Main 優先、EXE 里程碑化**：開發期間直接驗正常 Python 主程式；重大交付才建 Trial／EXE，不因文字、樣式小改造新版；1TB SSD 需保留模型、市場原件、研究結果與必要回退版本。

## 1. 已解決的審查衝突與正式設計決策

| 爭議／來源 | 統一決議 | 不應誤解成 |
|---|---|---|
| 個股研究既是「探索」第 4 子頁又是全站共同終點 | **全域共用 `Stock Research Detail`**；探索保留「直接查股」入口。從任何地方 push 全域詳情，**不強制切換左欄高亮主頁**；一個統一資料呈現協調層，資料語境須保留來源身份。 | 不能把四股一般報告與 1,951 檔價格研究的不同讀取資格直接混成同源或同期限。 |
| 取消巢狀 Tab 是否變成無限垂直捲動 | 詳情採**短標頭＋章節捷徑＋主從布局／Drawer**；表格頁使用單一主捲動容器；不是把六個 Tab 串成一篇數千像素長文。 | 不禁止所有 QTabWidget；禁止**使用者可見、連續多層巢狀分頁**。 |
| 個股雙欄比例：Opus 建議左主軸＋章節；另一審查建議 65/35 固定雙欄 | ≥1500 邏輯寬度目標主區約 65%／側欄 35%；1280 時優先**最小可讀寬度**（K 線／五問），必要時側欄改可停駐 Drawer 或上方摘要；不得硬切出過窄五問／K 線。 | 65/35 不是無條件硬限制；視窗邏輯高度、DPI 必須測。 |
| 首頁：風險先於機會或三卡 Bento Grid | **資料狀態 → 一句總結 → 持倉風險／待辦 → 市場／題材 → 研究線索／接續研究**為語意順序；寬畫面可以三卡＋下方雙欄呈現，窄畫面依風險優先調整視覺閱讀次序。 | 不保證沒資料時仍有「今日候選」或當日行情。 |
| 研究日誌與成果追蹤 | **合併為「研究紀錄與覆盤」一個子頁**，左時間軸、右當時／現在與到期成果；底層服務與保存格式保持各自的安全契約。 | 不是把不同 Journal/Forward 原件匯成不分來源的單一 DB。 |
| 「推薦」詞與產品長期推薦能力 | **目前未具正式資格的結果統稱「研究線索」**；「推薦」僅保留給取得相應正式資格的功能／歷史原件標籤（需要時明確加註其當時身份）；不移除未來正式 Recommendation 的產品方向。 | 不以改名來提升或否定任何金融資格。 |
| 台股紅漲綠跌與危險紅色衝突 | 市場方向色與**資料／風險狀態色 token 徹底分離**；方向只用文字＋▲▼＋正負號；風險用圖示＋狀態字＋獨立底色。 | 不憑顏色單獨傳達價格或風險。 |
| 資料狀態是 5×5 還是多種業務標籤 | UI 簡化為**資料狀態（可用／部分／過時／未核對／無資料）與內容性質（事實／規則訊號／模型估計／歷史模擬／我的判斷）**，但 DTO 另保留不可壓扁的 `use_eligibility`、`available_at`、`coverage` 與帳本身份；Blocked／Research-only 可追加醒目限用標示。 | 不能因為「已核對」就聲稱允許歷史 PIT 或正式推薦。 |
| 統一選股器導致跨資料域母體變成零 | **快速範本優先、三態條件判斷、跨域母體漏斗**，Unknown 留在計數並可獨立查看；正式推薦與 H20/Shadow 不混在篩選排名。 | 「保留 Unknown 顯示」不等於 Unknown 可以算條件命中。 |
| Opus 的常駐比較籃 vs 另一份的底部 Dock | 綜合選股／回測按實際可用空間使用**情境內比較籃**；同一個研究上下文保存條件，不要求全應用永久佔用底部 56px。 | 不建立跨金融域混比的共同計算引擎。 |
| 自動題材版本載入 | 開啟頁面預設**依合法身份、保存完成及可用時點選擇最新可讀版本**；版本切換為次要動作；拒絕時說明並提供明選回復，不擅自隱藏切換或繞過核驗。 | 「最新」不是當下最新資料、任意 `manifest` 或時間未到的快照。 |

## 2. 最終 IA：四大主頁面＋系統管理

```text
BALDR（全域 Shell：搜尋 Ctrl+K｜各域資料狀態｜通知｜偏好設定／系統管理）
├─ 1 今日總覽                        [單頁 Dashboard；無內層子 Tab]
├─ 2 探索與研究
│  ├─ 市場分析                       [指數、市場寬度、強弱股／產業、部分流向／處置]
│  ├─ 產業與題材                     [每日焦點／題材排行／25鏈／題材成分／筆記]
│  ├─ 綜合選股                       [方案、技術／營收／籌碼／官方／題材條件、比較]

├─ 3 我的投資
│  ├─ 自選與名單                     [☆股票、已存 Query／快照書籤、比較清單]
│  ├─ 持倉管理                       [手動真實帳、交易、損益、Health／Exit、籌碼監控]
│  ├─ 模擬帳與配置（Paper）          [隔離 Paper、情境／權重、壓力、封存]
│  └─ 研究紀錄與覆盤                 [Journal＋Forward時間軸、前後版、生命週期]
├─ 4 策略實驗室
│  ├─ 策略庫                         [策略家族、版本、規則／資格]
│  ├─ 回測分析                       [單股／組合／批次、績效、交易與訊號]
│  ├─ 績效比較                       [Registry、歷史 run、相容性、曲線]
│  └─ ML 研究                        [Personal H20、Shadow、OOS、Promotion Gate]
├─ ⚙ 系統管理（非第五個日常工作區）
│  ├─ 資料與更新                     [各域狀態、授權更新]
│  ├─ 排程與營運                     [Windows Tasks／Codex任務可觀測狀態]
│  ├─ 環境與來源診斷                 [Runtime、日誌、SHA、P0契約]
│  └─ 儲存維護                       [檔案大小、引用、清理候選；無自動刪除]
└─ 全域共用詳情層（從以上任何入口 push，不另開頂層）
   ├─ 個股研究（唯一目的地）
   ├─ 題材／產業鏈詳情
   ├─ 股票比較／歷史快照回訪
```

**深度預算**：主頁→子頁→詳情為主；子頁最多一個輕量視角切換（通常 ≤3–4 項），不得堆積永久巢狀 Tab。從 L1 可用數值到其來源／限制**目標 ≤2 次操作**；任何既有較深功能列入搬遷核對，不能直接移除。

## 3. 全域 Shell 與互動契約

### 3.1 固定外框

- 單一頂部列：Baldr／全域搜尋／資料域狀態／通知／齒輪。
- 單一子頁或返回／來源脈絡列；進詳情時此列**取代**原子頁選單，不再追加一層永久選單。
- Compact（以 1280×760 邏輯尺寸為主要驗收）導航 rail 收合並讓出內容寬；Standard（1500×900）保留常見左列，Wide（≥1920）增加並排資訊而非無限制放大字體。
- **外框總占高設計目標 ≈80–108px**，實測時含 Windows 標題列、字體與 125%／150% DPI，不得假定所有視窗都恰好有 650px 可用。
- 表格型頁面：外層不另開主捲動；`QTableView` 繼承主要高度，水平捲軸固定可見、凍結或重複顯示股號與名稱；長篇報告則用一個主要捲動區與章節導覽。

### 3.2 全域搜尋與路由

- `Ctrl+K`（可支援 `/` 但不在輸入欄位中搶按鍵）、股票代號／名稱／題材／產業鏈型別搜尋，選定後才導航；無合法資料時顯示原因。
- 全站點股票只開同一 `StockResearch Detail`。來自首頁、題材、選股、持倉、Journal、回測時，**保留使用者原本的左側主頁高亮**；頂部顯示明確 `[← 返回：來源名稱]`。
- 詳情導航需帶 `route_id`、`params`、`as_of/data_date`、`source/artifact identity`、`query`、`sort/filter/page`、`selection`、`scroll anchor`、`comparison basket`；單次頁內「上一檔／下一檔」在原清單中移動，不遞增回退堆疊。
- 當來源是封存快照時，在同一詳情明顯顯示**「正在查看 YYYY-MM-DD 歷史版本」**，提供「返回原清單」與**明確的「另行開最新可用資料」**，不能靜默換版並覆寫原研究上下文。
- 來源／版本身分失效、部分讀取或 stale worker 回傳時，須由既有 service 拒絕或清除失效結果；不可用 UI 回填舊版但不標示。
- 統一快捷鍵建議：`Alt+←` 返回、`Esc` 關 Drawer、清單 `Enter` 進詳情、`Space` 開預覽；需避開 Qt 既有輸入焦點與快捷鍵衝突。

### 3.3 全站保存與使用者意圖：兩類保存＋一種條件書籤

| 使用者操作 | UI 名稱與圖示 | 寫入／讀取語意 | 顯示入口 |
|---|---|---|---|
| 想持續追蹤股票 | `☆ 加入自選` | 保存標的 identity；下次查詢取當時合法可用的最新資料 | 我的投資／自選與名單 |
| 想保存自己的研究與依據 | `✎ 保存研究判斷` | 經既有 Journal append/revision、保留當時來源版本／原始內容／使用者看法；重開固定當時狀態 | 我的投資／研究紀錄與覆盤 |
| 想保存篩選做法 | `🔖 儲存篩選條件` | 保存 Query、母體、版本、比較籃等符合既有契約的引用，不能降格為只存股票代號 | 我的投資／自選與名單／已存研究條件 |

既有**研究書籤**若含原始 snapshot/證據，必須被保留並可回訪；不要因「兩類保存」規則刪除重要 snapshot。UI 上是使用者語意統一，不是底層資料扁平化。

## 4. 全站畫面布局（功能與交互為必需條款；尺寸為待量測目標）

### 4.1 今日總覽（單頁）

**首屏必答**：此資料截至何時？市場偏強或偏弱？我有需處理的持倉／研究嗎？有哪些**有日期、有依據、有反證**的研究線索？

```text
┌─ 資料域時效：價量 [日期/覆蓋] · 營收 [月份/覆蓋] · 題材 [版本] ──────────────┐
│ 盤後一句話：市場重點 + 當前持倉風險 + 可用研究線索（由具名資料組合）       │
├─ 市場體溫／寬度 ─┬─ 風險／待辦（最醒目）─┬─ 題材焦點／強弱（價量）────────┤
├─ 研究線索（3–5 筆；支持／反證／資料日／☆／→研究）──┬─ 最近研究／到期覆盤 ┤
└──────────────────────────────────────────────────┴──────────────────────┘
```

- 過時或無當日來源：標題採「**截至 YYYY-MM-DD 盤後的研究**」，不能仍寫「今日最強」；具名日期由 DTO 提供，而非硬編碼。
- 風險是語意優先（窄窗先於機會）；若無真實持倉資料或無資格風險訊號，就顯示「未建立／不可判定」而非製造警告。
- 「研究線索」僅展示符合其研究用途的既有產物，**沒有正式資格不能標買入價／出場價為正式建議**；也不能假設每次都有 3–5 檔。
- 首屏不可顯示 SHA、Git、PID、鎖競爭日誌、Agent 原始狀態。詳細工程紀錄在齒輪。
- 點卡片到持倉／研究／題材／覆盤，返回保留視圖上下文。
- 30 秒測試（真人驗收目標）：回答「資料日期與市場」、「有無待辦風險」、「可研究線索與限制」。

### 4.2 探索與研究／市場分析

- 指數與市場寬度 KPI（資料來源與有效分母明確）、強／弱股排行、強／弱產業排行；單一方向切換，不再四個平行來源 Tab。
- 主力券商、法人流向、處置／注意股預設收合在相關分區，各自顯示來源範圍、資料日期及資格；不能把部分上櫃法人標成全市場。
- 股票 → 共用個股；產業 → 題材／鏈別；選擇及排序返回原狀態。

### 4.3 探索與研究／產業與題材

```text
[目前合法可讀的映射版本／價量資料日]   [股票反查題材] [版本／證據 ⓘ]
[價量焦點卡] [成交金額] [同類齊發] [法人：僅合格來源／否則局部樣本]
┌─ 左：題材排行 ⇄ 25條產業鏈目錄 ─┬─ 右：選中題材／鏈別成分股與脈絡 ───┐
│ 漲跌、成交金額、共振等可用排序 │ 主／副標籤、上中下游位置、成分明細 │
│ 高低排序、有效數／總成分、覆蓋 │ [股票→個股] [就地編寫題材筆記]       │
└───────────────────────────────┴───────────────────────────────────────┘
```

- 慢變產業分類：**25 鏈、現有 90 核心題材，季度或手動更新對應**；每日表現讀已有合法價量快照；不必每日 LLM 分類。
- 不以第三方 232 題材數量作為本產品驗收目標。官網資料僅借鑑公開資訊階層。
- 題材順位與資金熱度分開；**成交額不是淨流入，法人股數不是 TWD，題材重疊不可跨題材總加當市場淨資金**。缺五日交易日曆不得造量能倍數。
- TPEx 法人不足、來源尚未接受時，主版面以合格**價量指標**排序；法人只作明確「部分樣本、僅供對照」分區或禁用排序，不能顯示全市場法人排行榜。
- 官方／人工種子／關鍵字／L1 保底分配來源須可查；非官方推定的上中下游不能畫成已查明之供應商實際交易網絡。
- 映射預設讀取**已完成且到達可用時點、經原 reader 接受的**最新快照；版本身份不符時拒用並提供具名回復。切換歷史快照不改原始版本。
- 點題材→成分股→個股→返回，原題材、排序、資料版本與選列均恢復。

### 4.4 探索與研究／綜合選股

```text
[研究母體與來源版本] [價量 N/M] [營收 n/m] [法人 n/m]
[快速方案：技術突破｜均線多頭｜已接通營收條件｜官方注意排查｜自訂]
┌─ 可收合條件（只開放已接通） ─┬─ 母體漏斗與 Unknown（不悄悄刪除） ───┐
│ 技術價量／營收／籌碼／處置 │ 股票結果，為何命中、為何未知、資料日 │
│ 題材分類／資格邊界         │ [☆自選] [+比較] [→ 個股]             │
└────────────────────────────┴───────────────────────────────────────┘
[已選 2–5 檔比較籃] [儲存 Query + 版本] [回到來源]
```

- 條件是 `MATCH / NOT_MATCH / UNKNOWN` 的**三態求值**，當跨資料域缺資料時，必須列出「原母體 → 各域可核母體 → 命中／不符合／未知」；使用者可切檢視 `符合／包括未知但明確標記／只看未知`，**未知不得算符合**。
- 3–5 個快速範本先取既有已實作、可驗證條件；不可預先硬允諾「營收雙增」、「題材動量」等尚未接線的條件。未接通條件 Disabled＋原因，不能輸出合成信號。
- `SC-01/02/03` 的 UI 來源合併，不代表它們的來源用途或母體自動互通；application 層需清楚定義交集與 eligibility。
- Personal H20／Shadow 歸策略實驗室，只能明選作「研究對照」且不混入正式結果／全域一般候選。
- 返回後保存 Query、source version、排序、頁碼、選列與比較籃；若原快照失效，清楚告知而不悄悄替換。

### 4.5 全域個股研究中心（Stock Research Detail）

**唯一研究呈現入口**：從任一主頁點股推入相同詳情；`探索與研究／個股查詢` 是直接搜尋的 landing page。原「一般四股報告」及「母體價量研究」的來源資格必須顯式區隔、逐區呈現，而非視覺上融合不同日期／授權來源。

```text
[← 原來源] [2330 台積電] [☆自選] [+比較] [✎保存判斷] [以此開回測]
[資料語境：歷史釘定/一般最新可用] [截至日期] [價量｜營收｜籌碼｜題材｜持倉 快捷錨點]
┌─ 主區：K 線＋價量／技術、營收財報、題材與籌碼、部位關聯 ─┬─ 快速研究側欄 ┐
│ (章節導覽可定位；一個主捲動區，不出現重疊捲軸)              │ 五問：趨勢     │
│ 缺財報 → 本區明示原因，不阻斷可用價量                      │ 動能／基本面   │
│ 歷史快照 → 固定當時證據，不重寫成今日結果                  │ 籌碼／風險     │
│ 進階：策略命中／H20研究／PIT／來源／版本 → 證據 Drawer       │ 主要反證／筆記 │
└───────────────────────────────────────────────────────────┴───────────────┘
```

- Standard/Wide 目標左主右副（約 65/35），在 1280×760 若排版不足，側欄可改置頂摘要或停駐抽屜，不得硬壓成無法讀取 K 線的雙欄。
- 頭部兩列；個股主要風險與資料限制 L1 必須看見。區域順序可依來源及持倉狀態調整，但同一套頁面，不另開第二套「示範股模式」。
- 「五問」不對無資料編摘要。欄位可用／不可用逐股判定；不把「有 1,951 檔價格」寫成「1,951 檔完整財報／籌碼」。
- 個股側欄可在同頁**保存判斷**、顯示當時紀錄與追蹤摘要；歷史詳情到「研究紀錄與覆盤」。
- 歷史快照標示資料語境，提供返回與**明選**一般最新可用查詢；「上一／下一檔」沿來源清單順序且不改原 Query。
- `View` 不直接拼湊來源身份或計算新的金融結論；application/adapters 投影 eligibility、lineage、coverage。

### 4.6 我的投資（四個子頁）

**自選與名單**：純自選、比較清單、已保存選股 Query／研究書籤三種物件同頁分區，操作不同、不可混為同一種收藏。

**持倉管理**：上方總覽與風險，中央主持倉表，點列以 Drawer 顯示 Health／Exit／成本／交易／籌碼。顯眼固定「**手動紀錄持倉，未與券商同步**」（若 repo 另有經證實之真實接線才修字）；不得將 Paper 部位顯示成此表的真實資產。

**模擬帳與配置**：固定「🧪 Paper 模擬，不會下單」文字橫幅＋**非僅靠顏色**的虛線／斜紋區別；展示原 Paper、配置研究、情境試算、壓力測試、研究封存。建 Paper 需先看條件與資料資格並經人工確認，缺同日合法 mark/cash 不造 NAV，可先保存研究而不建帳。

**研究紀錄與覆盤**：左時間軸統一索引股票、題材、持倉研究；右顯示「**當時固定證據 vs 現在的合法新資料**」、版本修訂及 Forward 5／10／20／60 交易日逐期成熟度、計畫目標日／實際取價日／缺件原因；研究、Paper、正式資格三種成果**不可混表統計**。只有索引整合，不要求破壞／遷移既有 Journal。

### 4.7 策略實驗室（四個子頁）

**策略庫**：既有註冊策略／版本／預期資料／資格與待證研究策略分區，未具資格的策略不可假裝已獲准正式決策。

**回測分析**：參數與數據來源設定可收合；執行後預設釋放圖表區，但持續顯示**期間、撮合方式、成本、滑價與來源資格**，不可只留下美觀報酬 KPI。結果將**已完成配對交易、期末未平倉、逐日訊號**分開呈現；0 配對不等於沒有訊號。沿既有單股、組合、批次模式，不新增第二個回測引擎。

**績效比較**：Registry 已保存 run；先顯示相容／不相容原因（期間、交易日集合、source identity、成本、撮合設定、基準），不相容時**拒絕誤導式並列**。可提供「返回參數設定」的入口；若原引擎未支援安全重跑，不提供虛假的「一鍵修正」功能。

**ML 研究**：Personal H20、Shadow、OOS、模型與基準比較、Promotion 相關診斷；始終標示「研究用／未取得正式決策資格」。在個股第三層按需引用，不進一般首頁候選或正式策略排名。

### 4.8 系統管理（齒輪）

- 先顯示一行「目前**哪些資料域**可查，哪些過時、部分或不可用」，再顯示各資料域逐項表與更新操作；**不設假裝全來源一致的單一『全站最新日期』**。
- 排程、正式資料更新必須沿既有授權服務／`release_v4` 等鎖與具名收據，不因 UX 改造自行改寫、重跑 Windows Task 或 Codex automation。
- SHA、P0、Runtime、Agent log、PID、詳細 error、來源路徑放可展開工程診斷，不在日常研究首屏。
- 儲存維護只讀盤點佔用、版本引用與清理預覽；舊 Trial、證據或私人帳本沒有引用／備份審查與 Owner 明示批准**不得刪除**。
- 偏好設定可放齒輪選單：主題、台股／美股漲跌色偏好、表格密度、隱私遮罩；家庭 Profile 只有在實際隔離契約已存在時才能啟用。

### 6.3 所有舊子頁的顯式處理

- **推薦分析 8 來源**：已保存推薦／策略研究 → 今日總覽摘要、原研究版保存回訪及策略證據；每日條件 → 技術；官方處置 → 官方；四均線＋處置 → 技術＋官方；均線＋月營收＋處置 → 技術＋營收＋官方；複合研究 v1 → 條件組；價格複合研究 v2 → 價位＋官方；H20 → ML 研究。
- **市場探索 8 頁**：指數 → 市場 KPI；強／弱股票 → 同一排行；強／弱產業 → 同一排行；主力 → 部分流向區；產業題材 → 產業與題材；母體盤勢 → 市場分母與選股來源。
- **個股研究 6 頁**：摘要 → 固定五問；價量 → 主圖；基本面 → 財報／營收區；籌碼事件 → 籌碼／題材區；部位／Health／Exit → 個股部位摘要＋持倉詳情；規則／ML／歷史 → Layer 3＋實驗室／研究紀錄捷徑。原「一般四股報告 vs 價格母體」雙頁分裂須由來源適配器調和，**不能僅刪 Tab**。
- **Portfolio 9 頁**：交易歷史 → 持倉；覆盤日誌 → 研究紀錄；宣告部位 → 持倉（明示非同步）；Paper → 模擬帳；配置研究封存 → 模擬帳／情境；壓力 → 模擬帳／風險；策略與價格監控 → 持倉；生命週期 → 研究紀錄／覆盤；持倉籌碼 → 持倉詳情＋個股籌碼。

**不可省略的 Sol 進場檢查**：盤點 CURRENT Git HEAD 的所有可達 widget、signal、slot、shortcut、保存與返回 callback，產出 `current owner → proposed V2 owner → contract → regression test` 表；漏項不是預設刪除，而是經具名裁決的保留、搬遷或停用。

## 7. 五條端到端研究旅程與驗收出口

| 流程 | V2 必須做到 | 資料不完整的安全出口 |
|---|---|---|
| 日常總覽 → 線索 → 個股 → 保存 → 返回 | 首屏支持／反證／資料日；一鍵研究、Journal versioned 保存，返回同清單與選列 | 無可用候選時顯示原因＋可用市場、最近研究；不造今日清單 |
| 市場／題材 → 成分股 → 個股 → 返回 | 25鏈／題材合法快照、成分股主副標籤、上一／下一檔與來源版本留存 | 法人或五日曆缺件只隔離相關排行與欄位，不阻斷價量與筆記 |
| 綜合選股 → 範本／條件 → 2–5股比較 → 個股 | 多域分母、UNKNOWN、相符證據、Query／排序／比較籃保留 | 缺營收／法人展示「未知」獨立群，絕不當不命中或零 |
| 個股研判 → 人工確認 → Paper → Forward → 覆盤 | 成果時間軸、當時 vs 現在；有合格帳本資料才建立 Paper | 缺 mark／現金等資格時阻 Paper，但可保存純研究／後續再覆盤 |
| 個股／策略 → 回測 → 保存 → 比較 → 返回 | 運算假設可見；保存 Registry，日期／成本／來源不相容拒比且有解釋 | 不相容時保留各 run，不畫錯誤比較圖，不偽造修復指令 |

## 10. Credits／SSD／驗收效率

### 10.1 Codex credits：上限、用法、記帳

- 先用可用的 Codex **訂閱內**使用額度；額外 credits 的**硬上限 12,500**，不是消耗目標；其他 AI 不重複做相同逐檔稽核。不可把 credits 換算成未經核對的固定 tokens／工時。
- **初版彈性預算**（僅針對*額外* credits，實際可按真實用量動態調整，不承諾一定使用）：M0 ≤500、M1 ≤1,500、M2 ≤3,000、M3 ≤2,000、M4 ≤1,500、M5 ≤1,500；合計 ≤10,000，**2,500 保留**給必要整合回歸與未知成本。若實際平台用量數據不可讀，必須標示「未能取得」，不得虛構；由 Owner 可見 credits 消耗或使用者提供狀態進行控制。
- 每階段回報：`完成的日常功能／原生旅程證據／重要缺口／額外 credits 實際消耗或 UNKNOWN／保留餘額／SSD artifacts 異動`；不許以建包次數或通過小測試數量充當產品進展。
- 突破 12,500 額外 credits 或必須執行新的收費動作前需 Owner 明確批准；保留額度的動用須具名理由，無需因普通合格工作反覆等人工派工。

### 10.2 磁碟／Trial

- 1TB SSD 的主要用途是日常市場資料、ML 模型與必要研究原件；UX 開發原則為**原始 Python Main**，不每改一顆按鈕就 PyInstaller 打包／600 秒移位測試。
- 只在 M1/M2/M3 跨重大依賴時視風險進行窄範圍 exe smoke，**正式產品候選 M5** 進完整封包驗收；若現有驗收契約要求更多，Sol 需提出受改範圍與理由而不是全面放棄 gate。
- 依引用關係、歷史證據與私人資料核對保留需求後，**建議**最新穩定＋必要 rollback 候選；舊版大小／依賴清查後才向 Owner 提出清理選項，不自動刪除。

### 10.3 分級 QA

- **Level A—小範圍 UI**：受改單元／靜態型別、相應 view/widget smoke、既有金融 guardrails 相關定向測試。
- **Level B—跨頁／保存／金融展示**：正常 Main 端到端正反案例、版本／source identity、取消／競態、保存／fresh process／返回，真／Paper 隔離、重要數值不誤導。
- **Level C—重大候選交付**：必要 Windows native GUI／不同 DPI／首啟動／EXE 與同版新程序、關鍵五旅程、回退與文件同步；未更動部分可重用具名收據，不強迫全部重跑。
- 金融來源、金額／單位、寫入隔離、PIT 防未來資料、完整性、正式交易權限**任何級別都不能放寬**；長期歷史證據採獨立 backlog，不和這三個 UX 測試層級混淆。
